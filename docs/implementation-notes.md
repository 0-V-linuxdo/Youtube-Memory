# 实现说明（净室重写中自行做出的决定）

本文件记录规格书（`docs/functional-spec.md`）未写明、存在歧义或互相冲突之处，以及实现时所做的选择。
实现只参考了规格书和 `tests/` 下的验收用例；没有查看任何原始代码。

## 一、总体

| # | 决定 | 依据 / 理由 |
|---|---|---|
| 1 | 主题改为 CSS 变量 + `prefers-color-scheme` 媒体查询，系统切换深浅色时**实时**生效；徽标与 `&t=` 选择弹窗也使用 N-5.3 的单色色板。 | 修复 C-Q4 / U-Q6；N-5.3 要求“跟随系统深浅色”。 |
| 2 | 第一部分以 rem 给出的尺寸一律按 1rem = 10px 换算成 px（例如徽标字号 1.3rem → 13px，💾 字号 1.5rem → 15px）。 | N-5.1.2：YouTube 的根字号为 10px，必须用 px。 |
| 3 | 设置弹窗在第一次打开时才创建 DOM，各标签内容在第一次切到该标签时渲染（之后保留，直到语言切换导致整体重建）。 | 规格允许；减少启动开销（L-Q20 的思路）。 |
| 4 | 同一文档中脚本只运行一次：在 `<html>` 上写 `data-ysrp-video-memory` 作为标记，不向页面泄露全局变量。 | C-13。 |
| 5 | 插件清单 `src/generated/plugins.ts` 由 `build.ts` 生成，但也提交进仓库，这样不先构建也能运行 `tsc --noEmit`。`bun run build.ts --gen-only` 只重新生成清单。 | N-0.3 + 任务要求 tsc 必须通过。 |
| 6 | CSS 通过 Bun 插件以文本形式打包（`import css from './style.css'`），由各插件在 `start()` 时插入 `<style>`，`stop()` 时移除；共享色板 `src/api/theme.css` 由入口插入一次。 | N-0.3、N-4.4。 |
| 7 | 存储后端的写操作**会抛出异常**（BUG-6），由调用方决定如何提示；设置类键（语言、字幕、插件）的写入仍静默失败。 | N-2.5.5。 |
| 8 | 测试用例里出现的 DOM 选择器（`.ysrp-tab`、`.ysrp-pane`、`.ysrp-row`、`.ysrp-ibtn.is-note` 等）全部视为对外契约来实现。 | 任务说明。 |

## 二、进度引擎（N-2）

| # | 决定 | 理由 |
|---|---|---|
| 9 | 引擎每 250 ms 检查一次地址栏视频 ID 与播放器状态；保存每 1.5 s 一次（另有 N-2.5.1 的即时写入）。恢复确认两次之间至少间隔 500 ms。 | N-2.4.3 要求“连续确认 2 次”，但未给间隔；间隔太短会在 YouTube 约 0.7 s 后把位置改回 0 之前就判定成功（A-9b）。 |
| 10 | 进入跟踪阶段时立即保存一次，然后按 1.5 s 周期保存；所有写入都遵守“与上次写入相差 ≥ 0.5 s”。 | N-2.5.2；暂停的标签页因此不会重复写入（A-7）。 |
| 11 | 会话结束（站内跳转、离开观看页）时用该会话最后一次“就绪”读数做最后一次写入；`yt-navigate-start` 时 URL 尚未变化，直接读取播放器。 | N-2.5.3。 |
| 12 | 播放器 `getVideoData().video_id` 为空字符串时视为“取不到”，不做 ID 比较（此时时长通常为 0，仍然不就绪）。 | N-2.3 第 2 条。 |
| 13 | 已看完（距结尾 < 5 s）且地址栏没有时间参数时 `seekTo(0)`；已看完但有时间参数时按链接时间播放，不弹窗。 | N-2.4.2 / N-3.1 没有写两者同时出现的情况。 |
| 14 | 第一个引擎检查延后到所有插件启动之后（`setTimeout 0`），保证云同步的“恢复前钩子”已登记。 | N-2.4.6、N-4.3（核心插件先启动）。 |
| 15 | 只有至少一个钩子真正返回了未完成的 Promise 时才显示“正在同步…”，避免未配置云同步时闪烁。 | N-2.4.6。 |
| 16 | 选择弹窗里两个按钮在 `pointerdown` 和 `click`（键盘激活）上都会生效（只生效一次）；Esc 通过 `document` 捕获阶段监听，焦点不在弹窗内也能用。 | N-3.4；测试用 `dispatchEvent('pointerdown')`。 |
| 17 | 选“上次进度”时立即跳转并（若原先在播放）继续播放，然后按 N-2.4.3 确认；选“链接时间”时不再跳转（播放器已经在链接时间）。 | N-3.4。 |
| 18 | 保存时 `videoName` 取“DeArrow > 原标题 > 记录中已有的非占位名称 > `Unknown Title`”，从不写入加载占位文字；原标题未知时不会用 `null` 覆盖已存的 `originalTitle`。 | C-Q14、S-Q11。 |
| 19 | 播放器就绪时把 `getVideoData().title`（YouTube 自己的原标题）登记为该视频的原标题，因此第一次保存就有正确标题（不必等 oEmbed）。 | C-81 的目的；Drive 文件名在第一次上传时就需要标题（A-21）。 |
| 20 | 直播判定：播放器显示的正是会话视频且 `getVideoData().isLive` 为真时，会话进入“直播”阶段，不恢复也不保存。 | N-2.4.4、D-3。 |

## 三、标题（DeArrow / oEmbed）

| # | 决定 | 理由 |
|---|---|---|
| 21 | DeArrow“没有标题”的结果缓存 30 分钟（有标题的缓存 6 小时）。 | 修复 C-Q3：不再每 1.5 秒请求一次。 |
| 22 | oEmbed 成功结果在本页会话内缓存；失败结果 5 分钟后允许重试，且失败**不会**把记录里的 `originalTitle` 写成 `null`。 | 修复 C-Q2、R-Q13。 |
| 23 | DeArrow 标题与原标题相同时只是丢弃，不再安排 1.5 秒后的强制重试；记录列表的 DeArrow 查询使用缓存（不强制）。 | 修复 C-Q12、U-Q11。 |
| 24 | 两处“标题相同”统一为“压缩空白、去首尾、忽略大小写”。 | 修复 U-Q10。 |
| 25 | `ysrp-current-video-status` 只在标题/状态真正变化时派发；导航事件与 `#title` 监听被引擎的会话检测取代（C-80 的 250 ms 防抖强制刷新不再需要）。 | 修复 C-Q6、C-Q11。 |
| 26 | `ysrp-dearrow-title-ready` 到达时只原地更新记录列表中对应的行（并持久化），不整表重建。 | 修复 U-Q13、R-Q7。 |
| 27 | 记录 `originalTitle` 的写入属于“元数据”，不更新 `updatedAt`；把 DeArrow 标题写入 `videoName` 属于“标题修改”，更新 `updatedAt`。 | N-1.1 只列出“进度、标题、笔记、字幕”。 |

## 五、云同步（N-7）

| # | 决定 | 理由 |
|---|---|---|
| 54 | Drive 请求优先 `GM_xmlhttpRequest`，否则 `fetch`；DeArrow / oEmbed / 字幕接口仍用页面 `fetch`（它们没有对应的 `@connect`）。 | N-7.12、C-8。 |
| 55 | 读取 `YSRP_DriveSettings` 时兼容“JSON 字符串里再包一层 JSON 字符串”的情况。 | 测试中的 GM 值即为此格式。 |
| 56 | 上传成功后 `driveSync.lastUploadAt` 记为本次上传所用快照的 `updatedAt`（而不是上传完成的时刻），这样上传过程中发生的修改一定会再次上传。 | N-7.6 未说明并发情况。 |
| 57 | 单一工作队列串行执行删除、全量同步和上传；删除优先，并会取消该视频尚未开始的上传。 | N-7.6 “同一时刻只有一个上传”、N-7.7。 |
| 58 | 下载应用云端记录时同时记录 `driveSync.remoteModifiedAt`。 | 防止下一次打开时重复下载同一版本。 |
| 59 | 首次全量同步不受“同一视频 15 秒”限制；旧版单文件按文件名在整个云端硬盘中查找；导入的旧记录按“批量操作”写入（不触发自动上传），随后的全量上传会把它们一并上传。 | N-7.9 未写文件位置与顺序。 |
| 60 | 文件夹查找不限定 `'root' in parents`（只按名称、类型、未删除）。 | N-7.3；也兼容测试中的文件夹。 |
| 61 | 状态“已推迟”在某次上传因 15 秒间隔被延后时显示。 | N-7.10。 |
