### 6. 时间格式化

- **C-37** 把秒数格式化为播放时间文本：
  - 小时 = 秒数 ÷ 3600 向下取整；分钟 = (秒数 mod 3600) ÷ 60 向下取整；秒 = 秒数 mod 60 向下取整（小数秒直接舍去，不四舍五入）。
  - 小时 > 0 时：`H:MM:SS`（小时不补零，分钟与秒补足两位）。例：3725 → `1:02:05`。
  - 小时 = 0 时：`M:SS`（分钟不补零，秒补两位）。例：65 → `1:05`；5 → `0:05`；0 → `0:00`。
  - 超过 24 小时不进位到天（如 90000 → `25:00:00`）。
  - 非法/负数输入的行为见 C-Q5。

### 7. 等待元素出现

- **C-38** 提供「等待某选择器对应元素出现」的能力：若当前文档中已存在匹配元素，立即返回该元素；否则对 `document.body` 的整个子树（子节点增删）进行监听，每次变动都重新查询，一旦出现即停止监听并返回该元素。

### 8. 国际化（i18n）基础设施

#### 8.1 语言偏好取值与规范化
- **C-40** 可选偏好值，顺序固定：`auto`、`zh`、`en`。回退语言为 `en`。
- **C-41** 规范化规则（输入先转字符串、去首尾空白、转小写；空值视为空串）：
  1. 等于 `auto` → `auto`；
  2. 以 `zh` 开头（如 `zh-CN`、`zh-tw`）→ `zh`；
  3. 等于 `en` 或以 `en` 开头 → `en`；
  4. 其他任何值（含空）→ `auto`。

#### 8.2 浏览器语言探测
- **C-42** 候选列表依次收集：`navigator.languages` 全部项（若为非空数组）、`navigator.language`、`navigator.userLanguage`（旧 IE）。取**第一个**非空白字符串候选；没有任何候选 → `en`。候选（去空白、小写）以 `zh` 开头 → `zh`，否则一律 `en`。

#### 8.3 偏好的读取与持久化
- **C-43** 读取：先尝试 `localStorage` 中键 `YSRP_LanguagePreference`；若无值（或读取异常），再尝试 GM 存储同名键；最终结果经 C-41 规范化（因此缺失时为 `auto`）。所有读取异常静默忽略。
- **C-44** 写入：值先规范化，然后**同时**写入 `localStorage` 与 GM 存储的 `YSRP_LanguagePreference`（与当前「存储模式」无关），任何一处失败都静默忽略。
- **C-45** 启动时读取一次偏好；若结果不在 C-40 列表中则强制为 `auto`。

#### 8.4 解析后的实际语言
- **C-46** 偏好为 `auto` 时实际语言 = 浏览器探测结果（C-42，每次求值时实时探测）；否则实际语言 = 偏好值（`zh` 或 `en`）。

#### 8.5 运行时语言状态
- **C-47** 运行时状态中维护语言信息：偏好、实际语言、事件名 `ysrp-language-changed`。启动时以及偏好变更时刷新；刷新时保留该信息中已有的其他字段。

#### 8.6 修改偏好
- **C-48** 修改偏好时先规范化；若与当前偏好相同则**什么也不做**（不写存储、不派发事件）。否则：更新内存中的偏好 → 持久化（C-44）→ 刷新运行时语言状态 → 在 `document` 上派发 `ysrp-language-changed`，detail 为 `{ preference: <新偏好>, resolved: <新实际语言> }`。派发异常静默忽略。
- **C-49** 对外暴露的 i18n 能力：按键翻译、扩充词条、设置偏好、获取当前偏好、获取实际语言、获取可选项（返回副本，`["auto","zh","en"]`）、探测浏览器语言、获取语言事件名、双语就地选择（§8.8）。

#### 8.7 词条表与按键翻译
- **C-50** 词条按语言（仅 `en`、`zh` 两桶）存储为嵌套对象，以点分路径访问（如 `language.options.auto`）。扩充词条时：传入对象的每个语言键若以 `zh` 开头（不区分大小写）归入 `zh` 桶，否则一律归入 `en` 桶；与已有内容做**深度合并**（普通对象递归合并，数组与基本值直接覆盖；后扩充者覆盖先前同路径值）。
- **C-51** 按键翻译的查找顺序：实际语言桶 → `en` 桶 → `zh` 桶 → 调用方提供的兜底字符串 → 原样返回路径本身。只有路径末端是**非空字符串**才算命中（空串视为未命中）。若未提供路径：有兜底字符串则返回兜底，否则返回该（空）路径。
- **C-52** 模板插值：文本中的 `{名称}` 占位（花括号内去空白后为键名）被参数中对应值（转为字符串）替换；参数中没有该键或花括号内为空 → 替换为空字符串。未提供参数对象时文本原样返回（占位保留）。兜底字符串同样进行插值。

#### 8.8 双语就地选择
- **C-53** 给定一个形如 `{ en: …, zh: … }` 的对象：若含有实际语言对应的键则取之（即使值为空串），否则依次取 `en`、`zh`。若取到的是函数，则以参数对象（无则空对象）调用并取返回值，调用抛错时视为空串。最终若为字符串则做 C-52 插值后返回；否则返回空串。传入非对象时返回空串。

### 10. 视频标题解析（原标题 + DeArrow 标题）

#### 10.1 标题文本规范化与比较
- **C-62** 规范化：转字符串，把所有连续空白（含换行、制表）折叠为单个空格并去首尾空白；空值得空串。
- **C-63** 两标题「相等」：两者都非空，且规范化并转小写后完全相同。任一为空 → 不相等。

#### 10.2 每视频标题来源表
- **C-64** 为每个视频 ID 维护两个候选：原标题（original）与 DeArrow 社区标题（dearrow），初始均为空。此表仅存于内存（本次页面会话），挂在运行时状态上供 UI 读取。
- **C-65** 设置原标题：存入规范化后的值（空串存为空）。若此时已有 DeArrow 标题且与新原标题「相等」，则清空 DeArrow 标题并安排一次 DeArrow 重试（C-67）。返回值：原标题是否非空。
- **C-66** 设置 DeArrow 标题：
  - 规范化后为空 → 清空 DeArrow 标题，返回「未接受」；
  - 与已有原标题「相等」→ 清空 DeArrow 标题、安排 DeArrow 重试，返回「未接受」；
  - 否则存入，返回「已接受」。
  - 视频 ID 为空时不做任何事，返回「未接受」。
- **C-67** DeArrow 重试节流：同一视频两次重试安排间隔至少 **5 分钟**（300000 毫秒）；不足则忽略。安排后在 **1500 毫秒**后强制（绕过缓存）重新请求 DeArrow 标题；重试失败仅记控制台错误 `Retry DeArrow fetch failed:`。

#### 10.3 有效标题解析
- **C-68** 给定视频 ID 与兜底标题：兜底先规范化，空则用 `Unknown Title`。
  1. 视频 ID 为空 → 返回兜底，来源/类型为 `fallback`；
  2. 若来源表中有 DeArrow 标题 → 返回它，来源/类型 `dearrow`；
  3. 否则若有原标题 → 返回它，来源/类型 `original`；
  4. 否则 → 兜底，`fallback`。
  即优先级：**DeArrow > 原标题 > 调用方给的兜底 > `Unknown Title`**。

#### 10.4 当前视频标题缓存
- **C-69** 写入缓存时，实际存的标题是按 C-68 解析出的有效标题（传入的标题只作兜底）。附带：
  - 来源：调用方指定，否则用解析结果的来源；置信度：调用方指定，否则 0；
  - 更新时间：当前时间；
  - 「是否占位」：解析类型为 `fallback`，或标题等于 `Unknown Title`，或等于 `正在获取标题…` 时为是。
  写入后立即派发当前视频状态事件（C-71），并返回该标题。
- **C-70** 「确保视频缓存」：若缓存中的视频 ID 不是目标 ID，则用占位 `正在获取标题…`、来源 `loading`、置信度 0 写入缓存（若来源表已有标题，按 C-69 会直接显示该标题）。

#### 10.5 当前视频状态事件
- **C-71** 在 `document` 上派发 `ysrp-current-video-status`，detail：
  - `videoId`：缓存的视频 ID 或 null；
  - `title`：缓存标题，空则 `Unknown Title`；
  - `isLoading`：缓存无视频 ID、或缓存为占位、或标题等于 `正在获取标题…` 时为 true；
  - `source`：缓存来源，空则 `unknown`；
  - `updatedAt`：缓存更新时间，空则当前时间。
  任何异常静默忽略。

#### 10.6 原标题获取（oEmbed）
- **C-72** 请求地址：`https://www.youtube.com/oembed?format=json&url=` + URL 编码后的 `https://youtu.be/<视频ID>`。请求不带凭据（credentials omit）、禁用缓存（cache no-store）。
- **C-73** 每视频结果在内存中缓存（本页会话内永久，含失败结果 null）；同一视频的并发请求共享同一个进行中的请求。视频 ID 为空 → 直接得到 null。
- **C-74** 成功（HTTP 2xx）：解析 JSON，若 `title` 为字符串则取去首尾空白后的值，否则 null；写入缓存，设置为来源表的原标题（C-65），并尝试把该原标题写回已存在的进度记录（若记录存在且字段值不同才写；不存在记录则不创建）。
- **C-75** 失败（非 2xx 视为错误 `oEmbed HTTP <状态码>`，或网络/解析异常）：控制台输出 `Failed to fetch original title:` 及错误；缓存 null，来源表原标题置空，并把记录中的原标题写为 null（若记录存在且原值不是 null）。结果为 null。

#### 10.7 DeArrow 标题获取
- **C-76** 请求地址：`https://sponsor.ajay.app/api/branding?videoID=` + URL 编码的视频 ID；不带凭据、禁用缓存。非 2xx → null；异常 → 控制台 `Failed to fetch DeArrow title:` 并返回 null。
- **C-77** 响应解析：响应须含非空数组 `titles`；按顺序取**第一个**满足以下条件的条目的 `title`：`title` 为字符串；`original` 不为 true；且（`locked` 为真，或 `votes`（非数字视为 0）≥ 0）。都不满足 → null。返回的标题不做其他加工（不去除 DeArrow 的 `>` 自动格式标记等）。
- **C-78** DeArrow 结果缓存：成功且被接受的标题按视频缓存，TTL **6 小时**（21600000 毫秒）。null 或未被接受的结果不缓存。
- **C-79** 请求流程（可选「强制」标志，默认否）：
  1. 视频 ID 为空 → null；
  2. 非强制且缓存未过期 → 把缓存标题设为来源表 DeArrow 标题、以来源 `dearrow-cache`、置信度 1 写入当前标题缓存，立即返回缓存标题（不发网络请求）；
  3. 若该视频已有进行中的请求 → 共享之（强制标志不会打断进行中请求）；
  4. 否则发起请求；拿到非空标题后按 C-66 设置，若被接受：写入 DeArrow 缓存（记录获取时间）、以来源 `dearrow`、置信度 1 写入当前标题缓存，并派发 `ysrp-dearrow-title-ready`（detail `{ videoId, title }`；派发异常时控制台 `Failed to dispatch DeArrow title ready event:`）。
  5. 结果为标题或 null；任何异常吞掉为 null；请求结束后移除进行中标记。
  注意：返回值是 DeArrow 原始结果，即使它因与原标题相同而未被接受也会返回该文本。

#### 10.8 标题刷新（防抖）
- **C-80** 标题刷新防抖 **250 毫秒**：每次触发都重置计时器；到期时若当前有视频 ID，则**强制**请求 DeArrow 标题。

#### 10.9 为某视频确保标题获取
- **C-81** 对给定视频 ID（为空则不做任何事）：确保视频缓存（C-70）→ 请求 DeArrow 标题（按调用方的强制选项，错误吞掉）→ 并行获取原标题；原标题非空且当前缓存仍是该视频且仍处于「加载中」（标题为 `正在获取标题…` 或为占位）时，以来源 `original`、置信度 0.7 写入当前标题缓存。

### 11. 视频切换检测（YouTube 单页应用导航）

- **C-82** 视频 ID 变更处理：若新 ID 与上次观察到的 ID 相同 → 忽略。否则记录新 ID（空记为 null）：
  - 新 ID 为空（离开观看页）→ 以 `Unknown Title`、来源 `idle`、置信度 0 写入当前标题缓存，结束；
  - 否则 → 为该视频确保标题获取（强制 DeArrow），并**立即执行一次进度保存**（为新视频「播种」记录）；保存异常时控制台 `Failed to seed progress on navigation:`。
- **C-83** 事件绑定（整个页面生命周期只绑定一次，首次获取视频名称时触发）：
  - 在 `window` 上以**捕获阶段**监听 YouTube 导航事件 `yt-page-data-fetched`、`yt-page-data-updated`、`yt-navigate-start`、`yt-navigate-finish`：每次触发 → 标题刷新防抖（C-80）+ 视频 ID 变更处理（C-82）；
  - `document` 的 `visibilitychange`：仅当页面变为可见时，执行同上两步；
  - `window` 的 `popstate`、`yt-history-popstate`（冒泡阶段）及 `yt-viewport-change`（捕获阶段）：仅执行视频 ID 变更处理；
  - 等待选择器 `#title` 的元素出现后，监听其子树（子节点变化、子树、文本内容变化）：每次变动 → 标题刷新防抖 + 视频 ID 变更处理；
  - 启动视频 ID 轮询（C-84）。
- **C-84** 视频 ID 轮询：只启动一次；启动时把「上次观察到的 ID」设为当前 ID，然后每 **500 毫秒**比较当前 URL 中的视频 ID，变化时执行 C-82。

### 12. 获取当前视频名称（供保存逻辑使用）

- **C-85** 若当前没有视频 ID → 返回 `Unknown Title`（且不绑定任何事件）。
- **C-86** 否则：确保事件已绑定（C-83）、确保轮询已启动（C-84）、为当前视频确保标题获取（**非强制**，可使用 DeArrow 缓存），然后**同步**返回当前标题缓存中的值（空则 `Unknown Title`）。因此首次调用通常返回 `正在获取标题…` 或已知的原/DeArrow 标题，异步结果在之后的调用中体现。由于进度每 1.5 秒保存一次并调用本能力，存储的 `videoName` 会随标题获取完成而自动更新。

### 已知问题 / 怪异行为

- **C-Q1** 开发须知要求「必须使用 `setTrustedHTML`，不得使用 `innerHTML`」，但脚本中根本没有定义该能力，且其他部分（笔记编辑按钮）实际仍对 `innerHTML` 赋空串。重写时应统一用 DOM API 或 Trusted Types 兼容方式。
- **C-Q2** 原标题获取失败（网络错误、限流、私有视频等）的结果 null 会被永久缓存到页面刷新为止，之后不再重试；同时还会把已存记录的 `originalTitle` 覆写为 null，抹掉之前成功获取的值。
- **C-Q3** DeArrow 没有标题（或标题被拒）时不做负缓存。由于每 1.5 秒的自动保存都会走「获取视频名称 → 请求 DeArrow（非强制）」路径，对没有 DeArrow 标题的视频，大约每 1.5 秒（前一请求结束后）就会向 `sponsor.ajay.app` 发一次请求。
- **C-Q4** 主题只在加载时判断一次，系统切换深/浅色后需刷新页面；且完全不参考 YouTube 自身的主题设置。
- **C-Q5** 时间格式化未处理非法值：NaN 输入得到 `NaN:NaN`；负数会产生如 `-1:0-5` 的怪异文本（-5 秒）。
- **C-Q6** 等待元素没有超时；用于标题监听的选择器 `#title` 过于宽泛，可能匹配到页面上第一个任意 ID 为 title 的元素而非视频标题；若该元素之后被 YouTube 替换，监听即失效（仍有 500ms 轮询兜底）。
- **C-Q7** 导航时「立即保存一次」进行播种：此时播放器可能仍报告上一个视频的播放时间（或 0），从而把错误的进度写入新视频的记录；若新视频之前有保存记录，可能被覆盖。
- **C-Q8** 「已恢复过保存进度」标志在单页导航到其他视频时从未被重置，因此只有页面首次加载的那个视频会自动恢复进度，之后通过站内导航打开的视频不会自动跳转。
- **C-Q9** 播放器辅助在播放器缺失时返回 0，调用方无法区分「真的在 0 秒」与「播放器不可用」，于是会把 0 写入记录。
- **C-Q10** 写入当前标题缓存时，传入的标题只作兜底，实际值由来源表决定，导致「来源/置信度」标签与真实标题来源可能不一致（例如标注来源 `original`、置信度 0.7，显示的却是 DeArrow 标题；或标注 `loading` 但已显示真实标题）。
- **C-Q11** 每次非强制命中 DeArrow 缓存都会重写当前标题缓存并派发 `ysrp-current-video-status`，即每 1.5 秒派发一次，即使没有任何变化。导航事件和 `#title` 变动则每次都强制绕过 DeArrow 缓存，使 6 小时 TTL 基本只对周期保存生效。
- **C-Q12** DeArrow 重试仅在其标题与原标题相同时触发，但 1.5 秒后的重试通常得到同样结果，几乎无意义（受 5 分钟节流限制）。
- **C-Q13** 视频 ID 只从 `?v=` 取，Shorts、嵌入页、`/live/` 链接等均不被记忆。
- **C-Q14** 占位文案 `正在获取标题…` 仅中文、`Unknown Title` 仅英文，不随界面语言切换；且这些占位字符串可能被作为 `videoName` 存进记录。
- **C-Q15** 语言偏好读取以 `localStorage` 优先，写入时同时写两处且不受存储模式控制；若两处不一致（例如 GM 存储被导入/同步），`localStorage` 值总是胜出。偏好为 `auto` 时浏览器语言变化不会派发语言变更事件。
- **C-Q16** 转录服务的 API Key（`sk-asdlfjalalfja`）和接口地址硬编码在脚本中，对所有用户公开。
- **C-Q17** 按键翻译把空字符串词条视为缺失并回退到其他语言；双语就地选择却会返回空字符串（只要该语言键存在），两者行为不一致。
- **C-Q18** 浏览器语言探测仅看第一个候选语言（例如 `["ja","zh-CN"]` 会解析为 `en`），任何非中文语言都归为英文。

## 1.2 存储后端、字幕接口、上次保存徽标、进度保存与恢复、界面插入

> 范围：原脚本"存储模式抽象""字幕设置与接口""上次保存信息""保存/加载进度""UI 插入辅助"五个模块的外部可观察行为。
> 本文只描述行为，不含实现代码。存储键、DOM 类名/ID、选择器、URL、HTTP 格式、事件名、YouTube 播放器 API 名属于外部契约，按原样列出。
> 需求编号 S-n 稳定，后续文档引用时请使用编号。

### 1. 常量与外部契约一览

- **S-1** 视频进度记录的存储键前缀为 `Youtube_SaveResume_Progress-`；单个视频记录的完整键为"前缀 + 视频 ID"（如 `Youtube_SaveResume_Progress-dQw4w9WgXcQ`）。视频 ID 为空时不生成键，相关操作直接放弃。
- **S-2** 存储模式偏好的键为 `YSRP_StorageMode`，取值 `local` 或 `gm`。
- **S-3** 字幕接口设置的键为 `YSRP_TranscriptSettings`，值为 JSON 字符串。
- **S-4** 视频标题缺省值为 `Unknown Title`（用于记录的 `videoName` 字段兜底）。
- **S-5** 记录更新事件名为 `ysrp-record-updated`，在 `document` 上派发（CustomEvent）。
- **S-6** 视频 ID 取自当前页面 URL 查询参数 `v`（`/watch?v=…`）；没有 `v` 参数的页面（首页、频道页、Shorts 等）视为"无当前视频"。
- **S-7** 播放器元素为 `#movie_player`；读取当前时间用其 `getCurrentTime()`，读取时长用 `getDuration()`，跳转用 `seekTo(秒数, true)`（第二参数 allowSeekAhead 为 true）。若元素不存在或方法不存在：当前时间视为 0、时长视为 0、跳转不执行。
- **S-8** 用户脚本需要的 GM 权限：`GM_getValue`、`GM_setValue`、`GM_deleteValue`、`GM_listValues`；匹配 `*://*.youtube.com/*`。

### 2. 存储后端抽象

#### 2.1 GM 可用性判定

- **S-9** 仅当 `GM_getValue`、`GM_setValue`、`GM_listValues`、`GM_deleteValue` 四个函数**全部**存在时，才认为"GM 存储可用"。该判定在脚本加载时做一次，之后不变。

#### 2.2 本地后端（localStorage）

- **S-10** 本地后端使用页面的 `window.localStorage`（即 youtube.com 源下的 localStorage，与 YouTube 自身数据共用命名空间）。
- **S-11** 读：返回该键的字符串值；键不存在或访问抛错时返回空（null）。
- **S-12** 写：直接写入字符串；任何异常（含配额超限、隐私模式禁用）**静默吞掉**，不向调用方报告失败。
- **S-13** 删：删除该键；异常静默吞掉。
- **S-14** 列键：返回 localStorage 所有键名；异常时返回空列表。
- **S-15** 按前缀列举：返回所有"键以指定前缀开头"的（键，值）对；异常时返回空列表。

#### 2.3 GM 后端

- **S-16** GM 后端所有操作在"GM 不可用"时退化为：读返回空、写/删无操作、列举返回空列表。
- **S-17** 读：返回 GM 存储中的值；值为 undefined 时返回空（null）；异常返回空。
- **S-18** 写/删：调用 GM 的写/删；异常静默吞掉。
- **S-19** 按前缀列举：先列出所有 GM 键，筛出以前缀开头的，再逐个读取其值，返回（键，值）对；异常返回空列表。

#### 2.4 当前模式的确定与持久化

- **S-20** 当前模式在首次被询问时惰性确定，规则：
  1. 先读 localStorage 中的 `YSRP_StorageMode`；
  2. 若 GM 可用且第 1 步读到的值为空，再读 GM 存储中的 `YSRP_StorageMode`；
  3. 若最终读到的值恰为 `gm` 且 GM 可用 → 模式为 `gm`；其余一切情况 → 模式为 `local`。
- **S-21** 首次确定模式后，立即把该模式同时写入 localStorage 的 `YSRP_StorageMode`；若 GM 可用，也写入 GM 存储的同名键（"双写"）。
- **S-22** 脚本启动时（引导阶段）会主动询问一次当前模式（因此 S-21 的双写在每次页面加载时都会发生），并把结果记入运行时状态"storageMode"。
- **S-23** 之后所有"通用读/写/删/列举"均路由到当前模式对应的后端；若模式未知则兜底为本地后端。

#### 2.5 切换模式与迁移

- **S-24** 切换模式接收目标模式与选项：是否迁移（默认是）、迁移后是否清除源数据（默认是）。设置界面调用时显式使用"迁移 + 清除源"。
- **S-25** 目标模式不是 `local`/`gm` 之一时，直接忽略。
- **S-26** 若当前模式尚未确定，先按 S-20 确定（此路径**不**触发 S-21 的双写）。
- **S-27** 目标模式与当前模式相同时什么都不做（也不重新持久化）。
- **S-28** 迁移时：从源后端按前缀 `Youtube_SaveResume_Progress-` 列出全部记录，逐条把**原始值**原样写入目标后端（单条失败被吞掉）；若"清除源"为是，再逐条删除源后端中这些键。只迁移视频记录；`YSRP_StorageMode`、`YSRP_TranscriptSettings` 及其他键不迁移。
- **S-29** 迁移完成后把当前模式改为目标模式，并按 S-21 规则双写 `YSRP_StorageMode`。
- **S-30** 切换模式不会检查目标 GM 后端是否可用（见已知问题 S-Q7）。

#### 2.6 导出

- **S-31** 导出生成如下对象（由设置界面负责序列化成 JSON 并复制/下载）：
  - `version`：固定字符串 `"1"`；
  - `exportedAt`：导出时刻的毫秒时间戳（数字）；
  - `storageMode`：当前模式字符串 `local` 或 `gm`；
  - `entries`：对象，键为完整存储键（含前缀），值为该记录在存储中的**原始值**（通常是 JSON 字符串，而非已解析对象）。
- **S-32** 只导出当前模式后端中以前缀开头的记录；另一个后端中的数据不导出。

#### 2.7 导入

- **S-33** 导入接收已解析的对象和选项"是否先清空现有记录"（默认否；设置界面中由一个复选框决定）。
- **S-34** 校验：对象必须存在、类型为对象、且含 `entries` 字段并且 `entries` 也是对象；否则抛出错误，消息为英文 `Invalid import payload`（界面会显示为 "Import failed: Invalid import payload" / "导入失败：Invalid import payload"）。`version`、`exportedAt`、`storageMode` 字段不校验、不使用。
- **S-35** 若选择"先清空"，在校验通过后、写入之前，删除当前后端中所有以前缀开头的记录。
- **S-36** 遍历 `entries` 的每个键：只处理以 `Youtube_SaveResume_Progress-` 开头的键，把值原样写入当前后端（覆盖同名记录，不做合并、不比较新旧）；其余键忽略。
- **S-37** 返回"已导入条数"= 被尝试写入的前缀键数量（由于后端写入不抛错，写入失败也会被计数）。界面据此显示 "Imported {count} record(s)." / "已导入 {count} 条记录。"。

### 3. 视频记录格式

- **S-38** 每个视频一条记录，值为 JSON 字符串，解析后为对象，已知字段：
  | 字段 | 类型 | 含义 |
  |---|---|---|
  | `videoProgress` | 数字（秒，可带小数，直接取自播放器 `getCurrentTime()`） | 上次保存的播放位置 |
  | `saveDate` | 数字（毫秒时间戳） | 最近一次保存时刻 |
  | `videoName` | 字符串 | 保存时脚本认定的视频标题（缺省 `Unknown Title`） |
  | `originalTitle` | 字符串或 null | 通过 oEmbed 获得的原始标题（见 S-55） |
  | `videoTranscript` | 字符串（可选） | 已获取的字幕全文（去首尾空白） |
  | `videoTranscriptUpdatedAt` | 数字（毫秒时间戳，可选） | 字幕写入时刻 |
- **S-39** 保存进度时以"旧记录的全部字段"为底，再覆盖本次的四个字段，因此其他模块写入的额外字段（以及字幕字段）都会被保留。
- **S-40** 读取单条记录时：键无值 → 视为无记录；JSON 解析失败 → 视为无记录；解析结果为假值（如字面量 `null`）→ 视为空对象。

### 4. 字幕接口设置

#### 4.1 常量

- **S-41** 默认接口基地址 `https://0-v-YouTube-Transcript-Generator-api.hf.space`；接口路径后缀 `/v1/chat/completions`。运行时默认配置中的完整地址为 `https://0-v-YouTube-Transcript-Generator-api.hf.space/v1/chat/completions`，经 S-44 规范化后主机名被转为小写，即实际默认值为 `https://0-v-youtube-transcript-generator-api.hf.space/v1/chat/completions`。
- **S-42** 默认模型 `transcript`；默认 API Key `sk-asdlfjalalfja`；默认超时 10 分钟（600000 毫秒）；超时允许范围 1–60 分钟（60000–3600000 毫秒）。
- **S-43** 字幕内存缓存有效期 30 分钟（1800000 毫秒）。

#### 4.2 超时换算

- **S-43a** 毫秒超时规整：先转为数字；非有限数或 ≤0 → 返回默认 600000；否则四舍五入到整数毫秒后夹到 [60000, 3600000]。
- **S-43b** 分钟 → 毫秒：分钟 × 60000 后按 S-43a 规整。
- **S-43c** 毫秒 → 分钟（用于显示/错误文案）：非有限数或 ≤0 → 10；否则 毫秒 ÷ 60000 四舍五入。

#### 4.3 接口地址规范化

- **S-44** 输入不是字符串、或去首尾空白后为空 → 结果为空字符串。
- **S-45** 若不以 `http://` 或 `https://`（不区分大小写）开头，前面补 `https://`。
- **S-46** 尝试按 URL 解析：
  1. 取路径并去掉末尾所有 `/`（因此根路径 `/` 变为空）；
  2. 若路径（小写比较）**包含** `/v1/chat/completions`：保留该路径（确保以 `/` 开头）；
  3. 否则若路径为空：路径设为 `/v1/chat/completions`；
  4. 否则（有自定义路径但不含后缀）：保留该路径**不追加后缀**；
  5. 输出完整 URL 字符串（查询串、片段保留；主机名按 URL 标准小写化），并去掉整个字符串末尾所有 `/`。
- **S-47** URL 解析失败时：去掉末尾所有 `/`；若（小写比较）已包含后缀则原样返回，否则直接拼接后缀 `/v1/chat/completions`。
- 示例：`example.com` → `https://example.com/v1/chat/completions`；`https://x.com/` → `https://x.com/v1/chat/completions`；`https://x.com/api/` → `https://x.com/api`；`http://x.com/V1/Chat/Completions/` → `http://x.com/V1/Chat/Completions`。

#### 4.4 设置的读取、合并与保存

- **S-48** 读取已存设置：先读 localStorage 的 `YSRP_TranscriptSettings`；为空且 `GM_getValue` 存在（只需这一个函数存在）时再读 GM 的同名键。值为字符串则按 JSON 解析（失败视为无）；值为对象则直接使用；其他视为无。
- **S-49** 设置清洗（用于用户输入）：只接受 `endpoint`、`model`、`apiKey` 三个字符串字段，去首尾空白后**为空则忽略**（不会覆盖已有值）；`endpoint` 额外按 S-44~S-47 规范化。超时：若输入中有 `timeoutMs` 字段且为有限正数，按 S-43a 规整；否则（仅当完全没有 `timeoutMs` 字段时）若有 `timeoutMinutes` 字段且为有限正数，按分钟换算规整；不合法则忽略。
- **S-50** 默认设置在脚本加载时一次性确定：`endpoint`=运行时默认完整地址规范化值；`model`=`transcript`；`apiKey`=`sk-asdlfjalalfja`；`timeoutMs`=600000。
- **S-51** 脚本加载时"注水"：以默认设置为底，用已存设置（不经清洗）逐字段覆盖；然后 `endpoint` 重新规范化（为空则用默认），`timeoutMs` 重新规整（为假值则用默认）；结果合并进运行时字幕状态（保留运行时字段 `lastVideoId`、`lastFetchedAt`、`lastTranscript`、`lastError`、`isFetching`）。
- **S-52** 对外"获取当前设置"返回四个字段：`endpoint`（规范化，空则默认）、`model`（空则默认 `transcript`）、`apiKey`（空则为**空字符串**，不回落到默认 Key）、`timeoutMs`（规整，空则默认）。若运行时字幕状态不存在则先注水。
- **S-53** "更新设置"：对传入的部分字段做 S-49 清洗；以"默认设置 ← 存储中的旧设置（原样）← 清洗后的新字段"顺序合并；把合并结果（仅含四个设置字段及旧存储中可能存在的其他字段）以 JSON 字符串同时写入 localStorage 的 `YSRP_TranscriptSettings`，若 `GM_setValue` 存在也写入 GM 同名键；然后合并进运行时状态；返回运行时状态的浅拷贝。写入异常静默吞掉。
- **S-54** 设置界面调用"更新设置"时机：任一输入框 `input`/`change` 后防抖 250 毫秒；超时输入框按"分钟"填写，可为小数，转换为毫秒后传入（非正数/非数字时不传超时）。（界面本身详见其他章节。）

### 6. 字幕获取（按视频）

#### 6.1 存储与缓存

- **S-56** 字幕持久化到视频记录：若文本去空白后非空，写入 `videoTranscript`（去空白后文本）与 `videoTranscriptUpdatedAt`（当前毫秒时间戳）；若为空，删除这两个字段。若该视频记录不存在或无法解析，则以空对象为底**新建**记录（该记录可能没有 `videoProgress`）。写入异常时控制台输出 `Failed to persist transcript to storage:`（实际因后端吞错几乎不会出现）。
- **S-57** 读取已存字幕：记录中 `videoTranscript` 为非空字符串（去空白后）时返回 {文本（去空白）, 获取时刻 = `videoTranscriptUpdatedAt` 或 0}；否则无。
- **S-58** 查缓存字幕（视频 ID 为空则无）：
  1. 若内存缓存中有该视频：距获取时刻超过 30 分钟则删除该缓存项并继续第 2 步；否则返回缓存文本；
  2. 读已存字幕；若有，将其放入内存缓存（获取时刻取记录中的时刻，为 0 时取当前时刻）并返回文本；
  3. 否则无。

#### 6.2 请求流程

- **S-59** 入参：视频 ID、选项 {是否强制刷新（默认否）, 视频标题（不使用）, 视频 URL}。
- **S-60** 视频 ID 为空 → 抛错 `无法识别当前视频 ID。`。
- **S-61** 非强制时：先按 S-58 查缓存，有则直接返回；再查"进行中请求表"，若该视频已有进行中的请求，返回同一个进行中结果（请求去重）。强制时跳过这两步。
- **S-62** 读取当前设置（S-52）；接口地址去空白后为空 → 抛错 `请先配置字幕接口路径。`。
- **S-63** 请求：
  - 方法 `POST`，URL 为规范化后的接口地址；
  - 请求头 `Content-Type: application/json`；若 API Key 去空白后非空，加 `Authorization: Bearer <去空白后的 Key>`；
  - 请求体（JSON）：`{"model": <设置中的模型，空则 "transcript">, "messages": [{"role": "user", "content": <视频 URL>}]}`；
  - 视频 URL：选项中的视频 URL 去空白后非空则用之，否则为 `https://www.youtube.com/watch?v=<视频ID>`；
  - 使用浏览器原生 fetch（非 GM_xmlhttpRequest），因此受 CORS 约束；支持 AbortController 时附带中止信号。
- **S-64** 请求开始时运行时状态置 `isFetching = true`、`lastVideoId = 视频 ID`。
- **S-65** 超时：在规整后的超时毫秒到达时，若响应头尚未到达，则中止请求并以错误失败，错误名 `TranscriptTimeoutError`，消息 `字幕接口在 {N} 分钟内无响应，已自动取消请求。`（N 为 S-43c 换算的分钟数）。响应头到达即清除计时器（读取响应体阶段不再受超时约束）。
- **S-66** 响应处理：读取完整响应文本；非空时尝试 JSON 解析，解析失败则把原始文本当作负载；空文本时负载为空。
- **S-67** HTTP 状态非 2xx：错误消息按优先级取 负载.`error.message` → 负载.`message` → 原始响应文本 → `HTTP <状态码>`，并以此失败。
- **S-68** 状态 2xx：按 S-70 提取文本；提取结果为空 → 失败，消息 `字幕接口未返回有效内容。`。
- **S-69** 成功：文本去首尾空白；写入内存缓存（获取时刻 = 现在）；按 S-56 写入视频记录；运行时状态 `lastTranscript` = 文本、`lastFetchedAt` = 现在、`lastError` = 空字符串；返回文本。
- **S-69a** 任何失败：运行时 `lastError` = 错误消息（无消息则错误的字符串形式），并把错误继续抛给调用方（界面显示 "Transcript failed: {message}" / "字幕获取失败：{message}"）。
- **S-69b** 无论成败：`isFetching = false`，并从进行中请求表移除该视频。
- **S-69c** 本次请求的进行中结果在发起后登记到进行中请求表（强制刷新时会覆盖同视频的旧登记）。
- **S-69d** 不做自动重试。

#### 6.3 响应文本提取规则（按顺序，命中即返回）

- **S-70**
  1. 负载为空/假值 → 空字符串；
  2. 负载为字符串 → 去空白后返回；
  3. 负载为数组 → 对每个元素递归提取，丢弃空结果，用换行 `\n` 连接后去空白；
  4. 负载含 `error.message` → **以该消息抛错**（即使 HTTP 为 2xx）；
  5. `transcript` 为字符串 → 去空白返回；为数组 → 元素以 `\n` 连接后去空白返回；
  6. `output_text` 为真值：数组 → `\n` 连接去空白返回；字符串 → 去空白返回；
  7. `output` 为数组：收集每个元素的 `content` 数组中每个 `text` 为字符串的片段，`\n` 连接去空白，非空则返回（为空则继续往下）；
  8. `choices` 为数组：每个 choice 取 `message.content`（字符串）；或 `message.content` 为数组时取各部分的 `text`（缺失按空串）以 `\n` 连接；或 `choice.text`（字符串）；其余为空。丢弃空项后 `\n` 连接去空白，非空则返回；
  9. `text` 为字符串 → 去空白返回；
  10. `data` 为非空字符串 → 去空白返回；
  11. 否则空字符串（如负载为数字、布尔真值或不含上述字段的对象）。

### 7. "上次保存"徽标文本

### 8. 进度保存

#### 8.1 触发时机

- **S-74** 脚本启动后立刻开启一个固定周期定时器，**每 1500 毫秒**执行一次"保存进度"，在所有 youtube.com 页面上持续运行，永不停止；不依赖播放器是否存在、是否暂停、是否已恢复进度。
- **S-75** 另有"视频 ID 监视器"（每 500 毫秒比较 URL 中的 `v`，见其他章节）：检测到切换到一个**非空**新视频 ID 时，立即额外执行一次"保存进度"（失败时控制台输出 `Failed to seed progress on navigation:`）。

#### 8.2 保存步骤

- **S-76** 当前无视频 ID（URL 无 `v`）→ 什么都不做。
- **S-77** 否则按序：
  1. 读取播放器当前时间（无播放器则为 0）；
  2. 取当前视频标题（标题模块提供，空则 `Unknown Title`；该调用顺带确保标题监听与抓取已启动）；
  3. 运行时状态 `currentVideoId` = 视频 ID，`lastSaveTime` = 现在；按 S-72 更新徽标（**在写存储之前**）；
  4. 从内存的"原始标题缓存"取该视频原始标题，无则为 null；
  5. 读取旧记录（解析失败视为无旧记录）；
  6. 新记录 = 旧记录全部字段，覆盖 `videoProgress`=当前时间、`saveDate`=现在、`videoName`=标题、`originalTitle`=第 4 步结果；
  7. 以 JSON 字符串写回当前后端；
  8. 在 `document` 上派发 `ysrp-record-updated` 事件，`detail` 为 `{ videoId, videoProgress }`（派发异常时控制台输出 `Failed to dispatch record update event:`）。
- **S-78** 无最小进度阈值、无"接近结尾则清除"逻辑、无"进度未变则跳过写入"逻辑：每个周期都会重写记录并刷新 `saveDate`。
- **S-79** 写入失败时理论上输出 `Failed to save video progress:`，但由于后端吞掉异常（S-12/S-18），实际不会出现，且事件照常派发。

### 9. 进度恢复

- **S-80** "读取已存进度"：取当前 URL 的视频 ID，读其记录，返回记录中 `videoProgress` 字段的值（可能是数字，也可能是 undefined/null/其他类型）；无视频 ID、无记录或 JSON 解析失败 → 空（null）。
- **S-81** "可以恢复"的条件同时满足：
  1. 本页面生命周期内尚未执行过恢复（一次性标志未置位）；
  2. `#movie_player` 存在；
  3. 读取已存进度结果不是 null（注意：undefined 被视为"有值"）；
  4. 播放器 `getDuration()` > 0。
- **S-82** 恢复动作：若已存进度不是 null，则对播放器调用 `seekTo(进度, true)`，并置位一次性标志。
- **S-83** 恢复调度：脚本启动后等待 `#movie_player` 出现（若已存在立即继续；否则用 MutationObserver 监听 `document.body` 子树的子节点变化，出现后断开监听，仅触发一次）；出现后先确保弹窗宿主与遮罩存在、初始化 UI，然后开启**每 500 毫秒**的轮询，满足 S-81 即执行 S-82 并停止轮询。若始终不满足条件，轮询一直持续。
- **S-84** 一次性标志在页面整个生命周期（包括 YouTube 单页导航切换视频）中**从不复位**。
- **S-85** 恢复时不检查进度是否接近片尾、不检查 URL 中的 `t` 参数、不提示用户。

### 已知问题 / 怪异行为

> 以下为原实现中看起来像缺陷或不合理的行为。净室重写时需由产品方决定"保持兼容"还是"修复"；凡涉及进度丢失的条目建议修复。

#### 可能丢失或覆盖播放进度

- **S-Q1 保存不等待恢复。** 保存定时器从脚本启动起每 1.5 秒运行，与恢复轮询（每 0.5 秒、需 `getDuration()>0`）相互独立。若播放器在首个保存周期前尚未就绪（时长仍为 0、或 `#movie_player` 尚未出现导致当前时间按 0 计），会先把 0 或刚开始的时间写入记录；之后恢复读到的就是被覆盖的值——原进度永久丢失。
- **S-Q2 单页导航后不再恢复，且新视频进度被覆盖。** 一次性恢复标志在整个页面生命周期内不复位（S-84）。在 YouTube 内点击进入另一个视频时，不会恢复该视频的已存进度；随后的保存（导航时立即保存 + 每 1.5 秒保存）会用新播放位置（通常从 0 开始）覆盖其已存进度。
- **S-Q3 导航瞬间的"种子保存"可能写入错误视频的时间。** URL 的 `v` 变化时立即保存，此刻播放器可能仍报告上一个视频的当前时间，于是把旧视频的时间点写到新视频的记录下。
- **S-Q4 无已存记录时的"自我恢复"。** 对没有记录的视频，恢复轮询会一直等待；首次保存创建记录后，轮询读到这个刚保存的值并 `seekTo` 过去，造成最多约 0.5 秒的回跳，并消耗掉一次性恢复机会（之后单页导航到真正有记录的视频也不会恢复，见 S-Q2）。
- **S-Q5 广告与片尾。** 保存不区分广告播放期间（播放器当前时间可能是广告时间）与正片，也不在接近片尾时清除进度；看完的视频下次会直接跳到结尾附近。
- **S-Q6 暂停时也持续重写。** 无论是否暂停、进度是否变化，每 1.5 秒都重写整条记录并刷新 `saveDate`，导致存储频繁写入（GM 模式下可能触发脚本管理器同步）、"最近保存"排序被持续扰动；若同一视频在多个标签页打开，后写者会互相覆盖。
- **S-Q7 切换到不可用的 GM 存储会删除全部记录。** 切换模式不检查 GM 是否可用；界面也未禁用 GM 选项。目标为 GM 但 GM 不可用时，迁移写入为空操作，随后"清除源"把 localStorage 中的全部记录删掉，数据丢失。同理，迁移中单条写入失败（如配额不足）被吞掉，但源数据仍会被删除。
- **S-Q8 写入失败完全静默。** 后端吞掉所有写入异常，保存流程无法得知失败；徽标仍显示新时间（且在写入前更新），`ysrp-record-updated` 事件照常派发。
- **S-Q9 导入覆盖不比较新旧。** 导入按键直接覆盖现有记录，不比较 `saveDate`；勾选"先清空"时先删全部再写入，若负载中的值无效（非字符串、非 JSON），清空后的数据也无法恢复。导入值原样写入：localStorage 模式下对象值会被存成 `[object Object]`，GM 模式下会存成对象；两者都会在下次页面加载的"无效记录清理"中被删除。导入计数包含写入失败的条目。
- **S-Q10 字幕先于进度写入时产生无进度记录。** 字幕持久化会在无记录时新建只含字幕字段的记录；此时"读取已存进度"返回 undefined，而恢复条件只排除 null，于是会执行 `seekTo(undefined, true)` 并消耗一次性恢复标志。字幕持久化遇到无法解析的旧记录时也会以新对象整体覆盖它。
- **S-Q11 `originalTitle` 被短暂（或永久）清空。** 保存时 `originalTitle` 取自内存缓存，页面刚加载、oEmbed 尚未返回时为 null，会覆盖记录中已有的原始标题；若随后 oEmbed 失败，则保持为 null。
- **S-Q12 存储模式判定偏向 localStorage。** localStorage 中只要有任意非空值就不会再看 GM；localStorage 为 `local` 而 GM 为 `gm` 时取 `local`。若用户换用不提供完整四个 GM 函数的脚本管理器，模式静默回落为 `local`，GM 中的记录"消失"（未删除但不可见）。

#### 其他怪异行为

- **S-Q13 字幕缓存有效期形同虚设。** 内存缓存过期后会立刻从视频记录重新读回同一份字幕再放入缓存，因此已持久化的字幕永不过期；只有强制刷新才会重新请求。
- **S-Q14 强制刷新的并发问题。** 强制刷新不去重，会覆盖进行中请求表中同视频的登记；较早的请求结束时会把较新请求的登记删掉，`isFetching` 也会被提前置为 false；两个请求谁后返回谁的结果写入存储。
- **S-Q15 超时只覆盖到响应头。** 响应头到达后计时器即被清除，读取响应体若长时间挂起不会被超时取消。
- **S-Q16 无法清空字幕设置字段。** 清洗规则忽略空字符串，用户清空 API Key/模型/地址输入框不会生效，旧值（或默认 Key `sk-asdlfjalalfja`）保留。另一方面，"获取当前设置"在运行时 Key 为空时返回空串而不回落默认值，与注水逻辑不完全一致。
- **S-Q17 接口地址规范化不一致。** 带自定义路径但不含 `/v1/chat/completions` 的地址不会追加后缀（如 `https://x.com/api` 保持不变），而解析失败的分支会追加；去除末尾 `/` 作用于整个 URL 字符串，可能改变以 `/` 结尾的查询串或片段；主机名被小写化（默认地址的大小写因此改变）。规范化中"路径含后缀但为空"的分支不可达。
- **S-Q18 "接口地址为空"的错误几乎不可达。** 获取设置时空地址会回落到默认地址，因此 `请先配置字幕接口路径。` 实际很难出现。
- **S-Q19 字幕相关错误文案仅有中文。** `无法识别当前视频 ID。`、`请先配置字幕接口路径。`、超时与 `字幕接口未返回有效内容。` 等消息不随界面语言切换。
- **S-Q20 2xx 响应中含 `error.message` 也视为失败**；非 2xx 且响应为无 `message` 的 JSON 时，错误消息是整段原始 JSON 文本。数组负载中任一元素含 `error.message` 会使整体失败。
- **S-Q21 设置按钮只能打开不能关闭；遮罩点击也不关闭。** 关闭完全依赖面板内部控件。按钮的事件处理在首次绑定时捕获了当时的弹窗元素；若之后弹窗被重建而按钮未重建，按钮仍会操作旧的（可能已脱离文档的）弹窗。
- **S-Q22 章节容器备选插入点几乎不生效**：只有左侧控制栏缺失时才会用到，且要求章节容器 style 属性严格为空字符串；一旦插入会强制把章节容器改为 `display: flex`。
- **S-Q23 时间格式未处理异常值**：负数或非数字进度会显示成诸如 `NaN:NaN` 或带负号的怪异文本。
- **S-Q24 恢复轮询可能永久运行**：在从不出现视频的页面（或记录永远无法满足条件时），每 500 毫秒的轮询从不停止。
- **S-Q25 字幕设置 GM 读写只检查单个函数**：读取只要求 `GM_getValue` 存在、写入只要求 `GM_setValue` 存在，与存储后端"四函数齐全"的判定标准不一致；字幕设置不随存储模式迁移，始终双写。

### 2. 本地化辅助

- **U-3** 提供"双语取值"能力：给定英文值与中文值（每个可以是字符串，也可以是接收参数对象、返回字符串的函数），按当前**解析后的界面语言**（`en` 或 `zh`）选取对应值；若值为函数则以参数对象调用（异常时得到空串）；最终字符串中的 `{name}` 形式占位符用参数对象中同名键替换（键名两端空白会被去掉；参数中不存在的键替换为空串；未提供参数对象时不做替换）。
- **U-4** 若当前解析语言对应的值缺失，回退顺序：英文值 → 中文值。最终结果不是字符串时返回空串。
- **U-5** 若国际化模块不可用（防御性分支），直接使用英文值（英文值缺省时用中文值），函数值以参数对象调用，失败返回空串；此分支**不做**占位符替换。
- **U-6** "笔记为空"占位文字：英文 `No notes yet`，中文 `暂无笔记`。
- **U-7** "大型表单控件"最大宽度常量：`48rem`（供其它标签页中的文本框 / 输入框使用）。

### 3. 语言状态与语言选项文案

- **U-8** 语言状态快照包含三项：
  - 偏好（preference）：优先取全局配置中记录的语言偏好；缺失时取国际化模块的当前偏好；再缺失则为 `auto`。
  - 实际语言（resolved）：优先取全局配置中记录的已解析语言；缺失时取国际化模块的解析结果；再缺失为 `en`。
  - 浏览器语言（browser）：调用浏览器语言检测；不可用时为 `en`。
- **U-9** 语言偏好的可选值固定为三项，顺序：`auto`、`zh`、`en`。语言变更时派发的自定义事件名为 `ysrp-language-changed`（若国际化模块提供事件名则用之，实际即此名）。
- **U-10** 各语言选项的显示文案（用于界面标签页的语言选择卡片）：

| 选项 | 标签（label） | 提示（hint） | 徽章（badge） |
|---|---|---|---|
| `auto` | 随界面语言：`Auto` / `自动` | 随界面语言：`Match the browser language automatically.` / `自动跟随浏览器语言。` | 随界面语言：`Auto` / `自动` |
| `zh` | 固定 `中文` | 固定 `始终使用简体中文。` | 固定 `中文` |
| `en` | 固定 `English` | 固定 `Always use English.` | 固定 `English` |

- **U-11** 未知选项值的回退：标签回退为 `Auto`/`自动`；提示回退为 `Match the browser language automatically.`/`自动跟随浏览器语言。`；徽章回退为该值的标签（即同样回退到 `Auto`/`自动`）。
- **U-12** 语言代码到显示名的映射：`zh` → `中文`；其它任何值 → `English`。
- **U-13** 语言变更后（收到 `ysrp-language-changed`），以 50 ms 防抖重建整个设置弹窗与播放器内信息条：记住弹窗是否打开及当前激活标签（读自弹窗的 `data-active-tab` 属性）→ 关闭并移除旧弹窗 → 重建信息条 → 以原激活标签为默认标签重新创建弹窗并重新绑定开关 → 若原先是打开状态，则重新打开并再次激活原标签。（重建细节属其它章节，此处只说明外壳需支持"默认标签"参数与 `data-active-tab` 回读。）

### 5. 标题比较规则与占位判定

- **U-17** 标题"相同"判定：两者都非空，且各自去掉首尾空白并转小写后完全相等（不压缩内部空白）。
- **U-18** DeArrow 占位标题判定：空值视为占位；否则去掉首尾空白并转小写后，等于 `unknown title` 或 `正在获取标题…` 时视为占位。
- **U-19** 显示用标题规范化：非字符串 → 空串；否则把连续空白压缩为单个空格并去掉首尾空白。

### 6. DeArrow 标题获取（网络）

- **U-20** 接口：`GET https://sponsor.ajay.app/api/branding?videoID=<URL 编码后的 videoId>`，不携带凭据（credentials omit），不使用 HTTP 缓存（no-store）。
- **U-21** 响应处理：HTTP 非 2xx → 视为无结果（null）；网络或 JSON 解析异常 → 在控制台记录 `Failed to fetch DeArrow title:` 并视为无结果。
- **U-22** 响应体为 JSON 对象，取其 `titles` 数组；数组缺失或为空 → 无结果。按数组顺序找到**第一个**满足以下全部条件的条目，返回其 `title`：
  - `title` 为字符串；
  - `original` 不等于 `true`；
  - 若未锁定（`locked` 为假值），则 `votes`（非数字视为 0）不得小于 0；已锁定条目不论票数都接受。
  - 没有满足条件的条目 → 无结果。
- **U-23** 全局 DeArrow 结果缓存：每个视频保存（标题、获取时间），有效期 6 小时。非强制请求且缓存未过期时，直接使用缓存标题（同时登记为该视频的 DeArrow 标题来源并刷新"当前视频标题"），不发网络请求。
- **U-24** 同一视频的网络请求进行中时，后续请求（无论是否强制）复用同一个进行中的请求结果。
- **U-25** 拿到非空标题后，先尝试登记为该视频的 DeArrow 标题来源：若该视频已知原始标题且两者按"规范化（压缩空白、去首尾）+ 忽略大小写"相同，则**拒绝**（视为 DeArrow 没有真正的替换标题），并安排一次重试（见 U-27）；否则接受。
- **U-26** 接受后：写入 6 小时缓存；刷新"当前视频标题"（来源标记 `dearrow`）；在 `document` 上派发自定义事件 `ysrp-dearrow-title-ready`，`detail` 为 `{ videoId, title }`（派发失败仅记录控制台错误）。请求结果（无论是否接受）返回原始标题文本或 null；任何异常都吞掉返回 null。
- **U-27** 重试调度：同一视频 5 分钟内最多安排一次重试（以最近一次安排时间计）；安排后延迟 1500 ms 发起一次**强制**（跳过 6 小时缓存）请求。
- **U-28** 标题来源登记的其它规则：登记原始标题时，若已有的 DeArrow 标题与之相同（同 U-25 比较），清除 DeArrow 标题并安排重试。标题解析优先级：DeArrow 标题 > 原始标题 > 传入的后备标题（规范化后为空则用 `Unknown Title`），结果同时带有来源类型 `dearrow` / `original` / `fallback`。

### 7. 设置面板侧的 DeArrow 可用性缓存与去重

- **U-29** 设置面板维护一份按视频 ID 的"DeArrow 可用性"内存缓存，状态为"可用（附标题）"或"缺失"。该缓存在页面生命周期内跨面板重建保留，不持久化。
- **U-30** 记录列表的"单次 DeArrow 查询"：对同一视频，若已有进行中的查询则复用；否则发起一次**强制**请求（跳过 6 小时缓存），完成后（无论成败）解除进行中标记。空视频 ID 直接得到 null。
- **U-31** "排队重试"：删除该视频在可用性缓存中的条目，然后按 U-27 安排重试。空视频 ID 忽略。
- **U-32** 记录标题解析（供记录列表使用）：后备标题 = 规范化后的传入标题，空则 `Unknown Title`。无视频 ID → 返回后备标题，来源 `fallback`。否则调用全局标题解析（U-28）；结果标题规范化后为空则用后备标题；来源与类型缺省为 `fallback`（类型缺省时取来源）。全局解析抛异常时记录控制台 `Shared resolver failed:` 并返回后备。

### 8. DeArrow 标题持久化到记录

- **U-33** "保证先存原始标题"：仅当存在该视频记录、记录 JSON 可解析、且记录中 `originalTitle` 不是非空字符串时才执行；此时获取原始标题（YouTube oEmbed：`GET https://www.youtube.com/oembed?format=json&url=<URL 编码的 https://youtu.be/<videoId>>`，不带凭据、no-store，取响应 JSON 的 `title` 去首尾空白），获取到则写回记录的 `originalTitle`。同一视频并发调用共享一个进行中的任务，完成后释放。获取失败记录控制台 `Failed to ensure original title before DeArrow:`。
- **U-34** 把 DeArrow 标题写入记录（视频 ID 与标题均非空才执行）：先执行 U-33，待其完成（成功或失败均可）后：
  1. 读取记录，不存在则放弃；
  2. 若记录有字符串 `originalTitle` 且与 DeArrow 标题"相同"（U-17）→ 不写入，执行"排队重试"（U-31）；
  3. 若记录的 `videoName` 已严格等于该标题 → 不写；
  4. 否则把 `videoName` 改为 DeArrow 标题，保留其它字段原样写回同一存储键。
  - 解析/写入异常记录控制台 `Failed to persist DeArrow title to storage:`。此写入**不**派发记录更新事件。
- **U-35** 设置面板监听 `ysrp-dearrow-title-ready`：`detail` 缺 `videoId` 或 `title` 时忽略；标题规范化后为空或为占位（U-18）时忽略；否则把可用性缓存设为"可用 + 该标题"，执行 U-34 持久化，并在当前没有正在进行的列表重建时，触发记录列表整体重建。（该监听在每次列表重建时重新注册，始终只保留一个。）

### 15. 记录进度百分比显示

- **U-66** 进度百分比计算（单条记录）：读取该视频记录的 `videoProgress`（秒），除以**当前页面播放器**（`#movie_player`）报告的总时长，乘 100，保留 1 位小数，显示为 `xx.x%`。记录不存在、播放器时长为 0（或无播放器）、记录 JSON 解析失败时显示 `0%`。
- **U-67** 进度原地刷新（不重建列表）：给定视频 ID 与可选的"实时进度秒数"：在列表中查找 `data-video-id` 匹配的项及其 `.ysrp-record-progress` 元素，找不到则不做任何事。若提供了实时秒数且该视频即当前页面视频（URL 参数 `v`）：播放器时长大于 0 时用"实时秒数 / 时长 × 100，保留 1 位小数"；否则回退到 U-66 的存储计算。其它情况一律使用 U-66。
- **U-68** 触发：每当收到自定义事件 `ysrp-record-updated`（`detail` 为 `{ videoId, videoProgress }`，由进度保存时派发）：缺 `videoId` 则忽略；列表中没有该视频的项 → 整体重建列表；否则按 U-67 原地刷新进度。收到 `ysrp-current-video-status`（`detail.videoId` 已定义且与上次渲染时的当前视频 ID 不同）时整体重建列表。这些监听在每次重建时重新注册，各只保留一个。
- **U-69** 列表重建具有防重入：重建进行中再次请求重建会被直接忽略。

### 已知问题 / 怪异行为

1. **U-Q1** 非当前视频的记录百分比也用**当前播放器**的总时长去除，因此除当前视频外的百分比都是错误的（可能远大于 100%）；在没有播放器的页面（如首页）所有记录都显示 `0%`。
2. **U-Q2** 记录缺少 `videoProgress` 但播放器时长大于 0 时，计算结果为 `NaN%`。
3. **U-Q3** 百分比格式不一致：正常值总是 1 位小数（如 `0.0%`、`12.0%`），而各种失败/无时长分支显示 `0%`（无小数）。
4. **U-Q4** 刷新指示器在同一次同步执行中被显示又被隐藏，浏览器中间没有机会重绘，因此实际上几乎从不可见。
5. **U-Q5** 点击遮罩层不会关闭弹窗，也没有 Esc 关闭；唯一关闭途径是 `✖` 按钮。
6. **U-Q6** 主题（含滚动条颜色、遮罩色）只在脚本加载时判定一次，系统切换深浅色后需刷新页面才生效；滚动条样式元素注入后也不会更新。
7. **U-Q7** 存储模式徽章中文为 `浏览器本地存储`，英文却是技术名 `localStorage`，两种语言信息量不对等。
8. **U-Q8** 语言选项 `zh` / `en` 的标签、提示与徽章是固定文本（`中文`/`English`、`始终使用简体中文。`/`Always use English.`），不随界面语言变化；翻译表中另有一套（如 `Chinese`、`EN`/`ZH`、`英文`、`始终使用英文。`）但未被使用。
9. **U-Q9** 标题获取中占位 `正在获取标题…` 只有中文版本，英文界面下也会出现此中文占位。
10. **U-Q10** 两套"标题相同"规则不一致：设置面板侧只去首尾空白并忽略大小写（不压缩内部空白），全局标题来源侧还会压缩内部空白；内部空白不同的两个标题在一处判"同"、另一处判"不同"。
11. **U-Q11** 记录列表中的 DeArrow 查询总是强制请求，绕过 6 小时缓存，每次列表重建对未确认的记录都可能重新请求接口（仅同时进行中的请求被合并）。
12. **U-Q12** 写入 DeArrow 标题会直接覆盖记录的 `videoName`；若原始标题获取失败（`originalTitle` 缺失），原有显示标题将永久丢失、无法区分来源。该写入也不派发记录更新事件。
13. **U-Q13** 每收到一次 `ysrp-dearrow-title-ready` 事件就整体重建一次记录列表，记录多时可能造成频繁重绘与重复网络请求；重建进行中到达的事件只更新缓存与存储，不会补一次重建。
14. **U-Q14** "可用性缓存"、单次查询去重等状态存在于页面级内存中，跨弹窗重建保留，但在 SPA 中永不清理。
15. **U-Q15** 若页面上尚无 `.last-save-info-container`（信息条），创建弹窗会静默失败，没有任何提示；需等待后续时机（章节容器就绪等）再次创建。
16. **U-Q16** 弹窗没有任何焦点管理与无障碍语义（无 dialog/tablist 角色、无 aria 属性、无键盘切换标签）。
17. **U-Q17** 头部标题的"已保存视频"计数只在创建与列表重建时更新；其它途径改变记录数量（如另一个标签页保存）不会实时反映。
18. **U-Q18** 弹窗根元素使用 all: initial 重置，`h3` 标题的字号与粗细依赖浏览器默认样式，未显式指定。

### 4. DeArrow 标题切换按钮

#### 4.1 判定 DeArrow 标题

**R-30** “占位标题”集合（大小写不敏感、去首尾空白后比较）：`unknown title`、`正在获取标题…`。

**R-31** “相同标题”的判定：两者均非空，且去首尾空白、转小写后相等。

**R-32** 本行所用的 DeArrow 标题按以下优先级取第一个可用值：
1. 运行时标题来源表中该视频的 DeArrow 标题；
2. 共享解析器解析结果类型为 DeArrow 时的标题；
3. 本会话 DeArrow 可用性缓存中状态为“可用”的标题；
4. 记录中的 `videoName`（规范化后非空且不是占位标题，并且与 `originalTitle` 不“相同”）。

若第 4 项因与原标题相同而被排除，则清除该视频的可用性缓存并安排一次 DeArrow 重试（见 DeArrow 模块）。

**R-33** 若得到 DeArrow 标题，将其写入本会话 DeArrow 可用性缓存（状态“可用”）。若此后发现该 DeArrow 标题与 `originalTitle` “相同”，则丢弃它（视为无 DeArrow 标题），并清除缓存、安排重试。

**R-34** 当且仅当可用性缓存中该视频状态为“缺失”（即已确认没有 DeArrow 标题）时，不创建 DeArrow 按钮，标题直接显示 `originalTitle`；若没有原标题则显示 `Loading original title…` / `正在获取原标题…`（随后由 R-47 更新）。

#### 4.2 外观与状态

**R-35** 按钮外观：透明背景、无边框、右外边距 `0.5rem`、宽高均 `2.4rem`、圆角 `0.6rem`、内边距 `0.25rem`、内容居中。

**R-36** 图标：26×26 像素的 DeArrow 标志 SVG（viewBox `0 0 36 36`，三层近似同心的圆形：最外层 `#1213BD`、中层 `#88c9f9`、最内层 `#0a62a5`），对辅助技术隐藏。

**R-37** 按钮有两个状态（体现在属性 `data-state`）：
- **pending（检测中）**：禁用；灰度滤镜 100%；不透明度 `0.4`；提示 `Checking DeArrow title…` / `正在检测 DeArrow 标题…`。
- **ready（就绪）**：可点击。
  - 正在显示 DeArrow 标题时：无滤镜、不透明度恢复默认；提示 `Show original title` / `显示原标题`。
  - 正在显示原标题时：灰度 100%、不透明度 `0.6`；提示 `Show DeArrow title` / `恢复 DeArrow 标题`。

**R-38** 初始化：
- 若已有 DeArrow 标题：标题显示 DeArrow 标题，按钮为 ready 且彩色。
- 否则：标题显示 `originalTitle`，没有则显示 `Loading original title…` / `正在获取原标题…`；按钮为 pending。

#### 4.3 后台查询 DeArrow 标题

**R-39** 当按钮存在且尚无 DeArrow 标题时，立即向 DeArrow 发起一次查询（同一视频的并发查询共享同一请求；强制绕过 DeArrow 缓存，见 DeArrow 模块）。

**R-40** 查询结果为空（无 DeArrow 标题）：可用性缓存记为“缺失”；从顶栏移除 DeArrow 按钮；若没有原标题，标题显示 `Original title unavailable` / `未找到原标题`。

**R-41** 查询得到标题：去首尾空白后记入缓存（“可用”），持久化到该记录（R-43），标题切换为 DeArrow 标题，按钮变为 ready 且彩色。

**R-42** 查询出错：控制台记录 `Failed to load DeArrow title for records list:`，按钮保持 pending（直到下次重建）。

**R-43** DeArrow 标题持久化：先确保记录中已存有原标题（若 `originalTitle` 为空，先按 R-48 获取并写入）；然后若记录的 `originalTitle` 与该 DeArrow 标题“相同”，则不写入并安排重试；若 `videoName` 已等于该标题则不写；否则把 `videoName` 改为该 DeArrow 标题并写回存储。记录不存在时什么也不做。

#### 4.4 点击切换

**R-44** 只有 ready 状态、且不在“加载原标题中”时点击才有效（加载中的标志体现在属性 `data-loading="true"`）。

**R-45** 当前显示 DeArrow 标题时点击：
- 若已知原标题：立即显示原标题，按钮变灰（R-37）。
- 若未知：标题临时显示 `Loading original title…` / `正在获取原标题…`，获取原标题（R-48）；获得后写入记录的 `originalTitle`，显示原标题；结果为空则显示 `Original title unavailable` / `未找到原标题`。若获取过程抛出异常，标题恢复为点击前的文字（控制台 `Failed to load original title:`）。结束后清除加载标志并刷新提示。

**R-46** 当前显示原标题时点击：切回 DeArrow 标题，按钮恢复彩色。

#### 4.5 原标题的后台获取

**R-47** 生成行时若记录中没有有效的 `originalTitle`，立即在后台获取原标题（R-48）。获取成功则写入记录；若此时该行正在显示原标题，标题更新为原标题，结果为空则显示 `Original title unavailable` / `未找到原标题`。（是否有 DeArrow 按钮均执行。）

**R-48** 原标题获取方式：请求 `https://www.youtube.com/oembed?format=json&url=` + URL 编码后的 `https://youtu.be/{视频ID}`，不带凭据、不使用缓存；取响应 JSON 的 `title`（去首尾空白）。同一视频本会话内结果（包括失败得到的空值）只请求一次并缓存；并发请求共享。成功或失败都会把结果（失败时为 `null`）写入记录的 `originalTitle`（记录存在且值有变化时）。

#### 5.5 获取流程

**R-60** 获取字幕：
1. 若已有获取在进行则忽略。
2. 若字幕模块不可用，显示状态 `Transcript module is not ready.` / `字幕模块未初始化。`，然后结束。
3. 进入加载态（R-52），显示状态 `Refreshing…` / `正在重新获取…`（首次获取也显示此文字）。
4. 调用字幕模块获取该视频字幕，传入：是否强制刷新、视频标题（生成行时解析出的标题）、视频 URL `https://www.youtube.com/watch?v={视频ID}`。
5. **成功**：文本框内容替换为结果；复制按钮仅在结果非空时启用；文本框不透明度为 1（有内容）或 0.7（无内容）；有内容时占位文字恢复默认；面板标记为“已加载”；状态显示 `Transcript updated ({time})` / `字幕已更新（{time}）`，`{time}` 为本地化的当前时刻（仅时间部分）。
6. **失败**：状态显示 `Transcript failed: {message}` / `字幕获取失败：{message}`（`{message}` 为错误信息）；面板不标记为“已加载”，所以下次展开会重新获取。
7. 无论成败，最后退出加载态。

**R-61** 刷新按钮点击：先展开面板（并记录展开状态），再强制获取（R-60，强制）。

#### 5.6 复制字幕

**R-62** 复制按钮点击：取文本框内容并去首尾空白。
- 为空：显示状态 `No transcript content to copy.` / `暂无字幕内容可复制。`。
- 否则通过异步剪贴板 API 写入：
  - 成功：按钮不透明度变为 `0.6`，250ms 后恢复 `1`；状态 `Transcript copied.` / `字幕内容已复制。`（经 R-57 后显示 `copied.` / `内容已复制。`）。
  - 失败：状态 `Copy failed: {message}` / `复制失败：{message}`。
- 无其他剪贴板回退方案。

### 9. 实时更新

**R-81** 每次重建结束时（重新）注册以下三个 `document` 级事件监听；新注册前先移除上一次注册的同类监听，确保每类只有一个。监听一直有效（对话框隐藏时也有效）。

### 已知问题 / 怪异行为

**R-Q1** 进度百分比对所有记录都用“当前页面正在播放的视频时长”作分母：非当前视频的百分比毫无意义，可能超过 100%；不在视频页（无播放器）时全部显示 `0%`。百分比也未做 0–100 的截断。

**R-Q2** 小数位不一致：正常值保留一位小数（`0.0%`），而异常/无时长情况显示 `0%`。

**R-Q3** 列表未排序，除当前视频置顶外完全依赖存储枚举顺序，与保存时间无关。

**R-Q4** 头部数量在重建时按“全部条目数”计算（含解析失败而未显示的条目），删除后又按“实际行数”计算，两者可能不一致。

**R-Q5** 无空状态提示；删除无确认。

**R-Q6** 重建会丢失笔记的未保存编辑内容、笔记面板与链接面板的展开状态（只有字幕面板展开状态会被恢复）。由于 DeArrow 标题就绪、记录更新（新记录）、视频切换都会触发重建，用户编辑笔记时可能被意外打断。

**R-Q7** 每次 DeArrow 查询成功都会触发 `ysrp-dearrow-title-ready` 并引起一次整表重建；列表中多条记录先后查询成功会引起连续多次重建。并且任何视频（包括不在列表中的视频）的 DeArrow 标题就绪也会触发重建。

**R-Q8** 状态消息去前缀规则会把 `Transcript loaded from cache.`、`Transcript updated (…)`、`Transcript copied.` 等截成 `loaded from cache.`、`updated (…)`、`copied.`（中文同理截掉开头的“字幕”），读起来不完整。

**R-Q9** 状态消息虽在逻辑上区分颜色（成功/失败/中性），实际全部以强调色显示（颜色参数被忽略）。

**R-Q10** 首次获取字幕时状态也显示 `Refreshing…` / `正在重新获取…`。

**R-Q11** 从缓存载入字幕时没有设置文本框不透明度（保持默认），与获取成功后的处理不同。

**R-Q12** DeArrow 查询出错时按钮永久停留在 pending（灰色禁用），直到下次重建。

**R-Q13** 原标题获取函数内部吞掉所有错误并返回空值，因此 R-45 中“异常时恢复点击前文字”的分支实际不会发生；失败时显示“未找到原标题”，并把 `originalTitle` 以 `null` 写回记录。原标题失败结果在本会话内被缓存，不会重试。

**R-Q14** 保存笔记时若记录已被删除（例如在其他标签页），会写入一条只含 `videoNote` 的新记录（笔记为空时写入 `{}`），产生没有进度的“残缺记录”。保存笔记也不发出 `ysrp-record-updated` 事件。

**R-Q15** URL 复制与字幕复制都只使用异步剪贴板 API，无 `execCommand` 等回退；URL 复制失败时界面无任何反馈。

**R-Q16** 链接按钮提示文字固定为 `Show / hide URL`，不随展开状态变化；字幕按钮的中文提示收起时为 `获取字幕`（而非“显示字幕”）。

**R-Q17** 重建期间的刷新指示器因重建是同步完成的，实际上几乎看不到。

**R-Q18** 查找行时把视频 ID 直接拼入属性选择器，没有转义；正常 YouTube ID 不受影响，但异常键名可能导致选择器错误。

**R-Q19** 删除记录不会清除该视频的字幕缓存与 DeArrow 缓存；之后若重新保存，会直接沿用旧缓存。

**R-Q20** `ysrp-current-video-status` 事件的 `detail.videoId` 为 `null`（如离开视频页）且上次渲染时有视频 ID 时也会重建；反之亦然。

## 1.5 “存储”标签：存储后端、迁移、导出、导入

> 本文档为净室重写所用的行为规格，只描述外部可观察行为与对外契约（存储键、DOM 类名、文件名格式、JSON 格式），不描述实现。
> 范围：设置面板中共享的按钮/输入框装饰规则、焦点环、操作状态消息、单选卡片，以及「存储」标签页的三张卡片（存储后端、导出数据、导入数据）及其全部交互逻辑；另含标签切换时的滚动条样式注入。
> 所有尺寸单位按原样以 rem 给出（YouTube 页面根字号通常为 10px，即 1rem ≈ 10px）。
> 所有双语文案以「英文 / 中文」形式给出，显示哪一种由全局界面语言决定（见语言相关规格）。带 `{xxx}` 的为占位符，运行时被替换为对应值；若参数缺失则替换为空串。

#### 4.4 迁移行为

- **T-37** 点击按钮时，以当前被选中的卡片决定目标模式（选中 GM 卡片为 `gm`，否则为 `local`）。若目标与当前生效模式相同，则什么也不做（无任何提示、无忙碌态）。
- **T-38** 否则进入忙碌态：按钮文字改为「Migrating... / 正在迁移...」，按钮不透明度 0.6，且禁止指针交互。
- **T-39** 执行迁移（同步完成），规则如下：
  1. 从**源后端**（当前模式）列出所有键名以 `Youtube_SaveResume_Progress-` 开头的条目（即所有视频进度记录）。
  2. 逐条以相同键名、原样的值写入**目标后端**；目标后端中已有的同名键被覆盖，目标后端中其它已存在的记录保持不变（相当于合并到目标）。单条写入失败被静默忽略。
  3. 然后从源后端删除第 1 步列出的全部键（「移动」语义，源后端清空这些记录）。删除失败静默忽略。
  4. 不以该前缀开头的键（如其它设置项）不迁移、不删除。
  5. 将新模式持久化：同时写入 localStorage 和（若 GM 接口可用）GM 存储中的键 `YSRP_StorageMode`，值为 `local` 或 `gm`。
- **T-40** 两个后端的定义：
  - `local`：当前站点（youtube.com）的 `window.localStorage`。
  - `gm`：用户脚本管理器提供的 GM 值存储（需要 GM_getValue / GM_setValue / GM_listValues / GM_deleteValue 四个接口均可用才视为可用）。GM 不可用时，对 GM 后端的读返回空、写和删为空操作、列举返回空列表。
- **T-41** 启动时的模式判定（供参考，本页依赖）：先读 localStorage 的 `YSRP_StorageMode`；若没有且 GM 可用，再读 GM 中的同名键；值为 `gm` 且 GM 可用时为 `gm`，其余情况为 `local`。首次判定后会立即把结果写回两处持久化。
- **T-42** 迁移成功后：两张单选卡片的勾选状态同步为新模式并刷新样式；面板标题旁的存储模式徽章文字更新为「GM Storage / GM 存储」（gm）或「localStorage / 浏览器本地存储」（local）；「记录」列表按新后端重建（包括标题中的记录数量「Saved Videos - ({count}) / 已保存视频 - ({count})」）。
- **T-43** 迁移抛出异常时仅在控制台记录错误「Failed to switch storage:」，界面无任何错误提示。
- **T-44** 无论成功或失败，在 500ms 后恢复按钮：文字恢复为点击前的文本，不透明度 1，恢复指针交互。
- **T-45** 迁移完成没有任何成功提示消息（本卡片没有状态消息行）。

  2. 「Download JSON / 下载 JSON」，图标 `fa-solid fa-file-arrow-down`（颜色随文字），title「Download export JSON as file / 下载导出的 JSON 文件」。

#### 5.2 导出 JSON 格式（对外契约）

- **T-52** 导出内容取自**当前生效的后端**中所有键名以 `Youtube_SaveResume_Progress-` 开头的条目，生成如下对象，并以 2 空格缩进的 JSON 文本输出：

```json
{
  "version": "1",
  "exportedAt": 1760000000000,
  "storageMode": "local",
  "entries": {
    "Youtube_SaveResume_Progress-<videoId>": "<该记录在存储中的原始值>"
  }
}
```

  - `version`：固定字符串 `"1"`。
  - `exportedAt`：导出时刻的毫秒时间戳（数字）。
  - `storageMode`：导出时的模式，`"local"` 或 `"gm"`。
  - `entries`：键为完整存储键（含前缀），值为存储中的原值，原样输出（通常是一段 JSON 字符串，即记录对象被序列化后的字符串，格式见记录存储规格；不做二次解析）。没有记录时为空对象 `{}`。
  - 字段顺序为 version、exportedAt、storageMode、entries。

#### 5.3 复制 JSON

- **T-53** 点击「复制 JSON」：生成导出 JSON 并写入系统剪贴板（异步剪贴板 API）。
- **T-54** 成功：按钮不透明度变为 0.7，300ms 后恢复 1；状态行显示「JSON copied to clipboard. / JSON 已复制到剪贴板。」，颜色为 copyButtonColor（亮 `#2980b9` / 暗 `#1abc9c`）。
- **T-55** 失败（任何异常，包括剪贴板 API 不存在或被拒绝）：控制台记录「Copy export failed:」；状态行显示「Copy export failed: {message} / 复制导出失败：{message}」，`{message}` 为错误的 message，若无则为错误本身的字符串形式，再无则为空；颜色为危险色 `#e74c3c`。

#### 5.4 下载 JSON

- **T-56** 点击「下载 JSON」：生成导出 JSON，并按本地时间生成文件名，格式严格为：

  `[Youtube] Video Memory「YYYY MM DD」「HH:MM:SS」.json`

#### 6.5 导入行为

- **T-79** 点击「从文本导入」：取文本域内容去首尾空白；若为空，状态行显示「Nothing to import. / 没有可导入的内容。」（弱化文字色），不做其它处理；否则执行导入（T-81）。
- **T-80** 选择文件后：文件名显示区先显示所选文件名（未选文件则恢复默认文本并结束）；以文本方式读取文件；**随即**清空文件输入的值（以便再次选择同一文件可触发）并把显示区恢复为「No file chosen / 未选择文件」。文件读取完成后，把文件文本（空则为空串）填入文本域，并执行导入（T-81）。
- **T-81** 导入处理：
  1. 将文本按 JSON 解析；解析失败即导入失败。
  2. 校验：结果必须是对象，且含 `entries` 字段且其为对象（不检查 `version`、`exportedAt`、`storageMode`，`storageMode` 被忽略）。不满足则失败，错误信息为英文「Invalid import payload」（不翻译）。
  3. 若「覆盖」复选框已勾选：先删除**当前生效后端**中所有以 `Youtube_SaveResume_Progress-` 开头的记录。
  4. 遍历 `entries` 的每个键：只处理键名以 `Youtube_SaveResume_Progress-` 开头的条目，将其值原样写入当前生效后端（同名记录被覆盖）；其余键静默跳过。成功写入的条数计入导入数量。
  5. 未勾选「覆盖」时为合并：后端中已有但导入文件中没有的记录保留；同名记录以导入值覆盖（不比较时间/进度新旧）。
- **T-82** 导入成功：状态行显示「Imported {count} record(s). / 已导入 {count} 条记录。」（count 为第 4 步计数），绿色 openButtonColor；「记录」列表重建（含标题数量）。文本域内容保留不清空。
- **T-83** 导入失败（解析错误或校验失败等）：状态行显示「Import failed: {message} / 导入失败：{message}」，`{message}` 为错误 message（如浏览器原生的 JSON 解析错误文本或「Invalid import payload」），无 message 时为错误本身；危险色；控制台记录「Import failed:」。失败发生在第 1、2 步时不会删除任何数据。
- **T-84** 导入始终写入当前生效的后端，与导出文件中 `storageMode` 无关；导入不改变存储模式。

### 已知问题 / 怪异行为

1. **GM 不可用时迁移到 GM 会丢数据**：GM 卡片始终显示且可选。若用户脚本管理器未提供完整 GM 接口，选择 GM 并应用后，写入 GM 为空操作，但源 localStorage 中的记录仍被删除；模式被记为 `gm`（仅写入 localStorage），而下次加载时因 GM 不可用回退为 `local`，看到的是空记录。数据实际已永久丢失，且界面无任何提示。
2. **迁移无成功/失败反馈**：成功不显示任何消息（只有徽章和列表变化）；失败只在控制台记录；目标与当前相同时点击无任何反应。
3. **忙碌态几乎不可见**：迁移是同步执行的，「正在迁移...」文字在迁移完成前通常来不及绘制，用户看到的主要是之后 500ms 的半透明禁用态。
4. **迁移是合并覆盖而非替换**：目标后端中已有的同名记录被源数据覆盖（不比较新旧），目标后端中独有的旧记录被保留，可能导致切换来回后出现「复活」的旧记录。
5. **覆盖导入可清空全部记录**：勾选「覆盖」且导入文件的 `entries` 为空对象或其中没有任何带前缀的键时，现有记录全部被删除，结果提示「已导入 0 条记录」，无二次确认。
6. **校验很宽松**：`entries` 为数组也能通过；条目的值不做任何格式校验，非字符串值（如对象、数字）会被直接写入——在 localStorage 后端会变成 `"[object Object]"` 之类的字符串，导致该记录在列表中无法解析；GM 后端则会存入非字符串值。`version` 字段不检查。
7. **校验错误信息不本地化**：「Invalid import payload」及浏览器原生 JSON 错误文本在中文界面下仍为英文，仅前缀「导入失败：」为中文。
8. **iOS「新标签页打开」分支实际上几乎永远走不通**：以 `noopener` 打开新窗口时浏览器按规范返回空引用，因此总被判定为「未打开」而继续回落为普通下载；若浏览器其实已打开了新标签页，用户可能同时得到新标签页和一次下载尝试，状态行却显示「导出下载已开始。」。
9. **iOS 分享成功的提示语义不准**：分享 API 的 Promise 在用户完成分享操作后才兑现，此时提示「已打开系统分享面板，请选择“存储到文件”」已是事后提示。
10. **文件名显示区几乎永远看不到文件名**：选中文件后显示文件名，但同一时刻立刻被重置为「未选择文件」，用户实际看不到所选文件名。
11. **文件读取错误未处理**：读取失败时没有任何提示。
12. **文件名包含冒号**：下载文件名中的 `HH:MM:SS` 在 Windows/macOS 等文件系统上会被浏览器替换为其它字符（如 `_` 或 `-`），实际保存的文件名与格式不完全一致。
13. **复制在无剪贴板 API 时的报错文本晦涩**：非安全上下文或剪贴板 API 不存在时，提示的是原生的 TypeError 文本。
14. **状态消息永不自动消失**，也不会在切换标签时清除。
15. **焦点环颜色与按钮强调色不一致**：所有设置操作按钮的焦点环都使用通用悬停底色（亮色下为浅蓝），绿色导出按钮聚焦时也是蓝色焦点环；且悬停底色同样为浅蓝/浅白而非按钮自身强调色。
16. **键盘可达性差**：存储单选框被 `display:none` 隐藏，单选卡片无法通过键盘聚焦或切换；「覆盖」复选框完全透明且无焦点指示；「应用并迁移」按钮无焦点样式。
17. **文本域焦点环覆盖内阴影**：附加焦点环后，文本域原有的 inset 内阴影被焦点环的透明阴影替换，实际不再显示。
18. **导出卡片标题被追加两次**：构建时同一标题节点被重复追加，因 DOM 移动语义最终只出现一次，无可见影响（重写时只需追加一次）。
19. **导入后文本域不清空**，文件导入时文本域被文件内容覆盖，用户之前粘贴的内容丢失。
20. **主题不随系统实时变化**：明暗配色在面板构建时固定。
21. **提示文字含义错位**：覆盖复选框旁的提示讲的是「导入到当前后端」，并未解释勾选「覆盖」会先删除现有记录。
22. **只迁移/导出/导入进度记录**：以 `Youtube_SaveResume_Progress-` 为前缀之外的数据（如字幕接口设置、语言偏好等）不参与迁移、导出或导入。

#### 2.2 字幕设置的保存

- **L-19** 四个输入框任一触发 `input` 或 `change` 事件时，启动 250 ms 防抖计时器（重复触发会重置计时）；计时结束时一次性读取四个字段当前值并提交保存。
- **L-20** 超时值处理：把输入框内容解析为浮点数（允许小数分钟）；若是有限且大于 0 的数，则换算为毫秒并夹在 [60000, 3600000] ms（1–60 分钟）范围内并取整；否则（空、非数字、≤0）视为"未提供"，保留原有值。
- **L-21** 提交时对文本字段的清洗：接口地址、模型、密钥三者各自去除首尾空白；去空白后为空的字段视为"未提供"，保留原有存储值（不会清空）。
- **L-22** 接口地址规范化规则：
  1. 若不以 `http://` 或 `https://`（不区分大小写）开头，则前置 `https://`。
  2. 去除路径末尾的所有 `/`。
  3. 若路径（小写比较）不包含 `/v1/chat/completions`：路径为空或仅为 `/` 时设为 `/v1/chat/completions`；否则保留原路径（确保以 `/` 开头）。
  4. 若路径已包含该后缀，则保留原路径。
  5. 最终整个 URL 去除末尾的 `/`。
  6. 若无法解析为 URL：去除末尾 `/` 后，若已包含 `/v1/chat/completions` 则原样返回，否则直接拼接该后缀。
- **L-23** 保存合并顺序：默认设置 ← 已存储的设置 ← 本次清洗后的有效字段；合并结果整体写入存储，同时更新内存中的当前字幕配置（立即生效，下一次字幕请求即使用）。
- **L-24** 默认字幕设置：接口地址 `https://0-v-YouTube-Transcript-Generator-api.hf.space/v1/chat/completions`；模型 `transcript`；密钥 `sk-asdlfjalalfja`；超时 600000 ms。
- **L-25** 存储位置：以 JSON 字符串写入 `localStorage` 键 `YSRP_TranscriptSettings`；若用户脚本管理器提供 `GM_setValue`，同时以同名键写入 GM 存储（同为 JSON 字符串）。读取时优先 `localStorage`，为空再读 GM 存储；读到字符串则解析 JSON，读到对象直接使用，解析失败视为无。写入失败静默忽略。
- **L-26** 保存后不会回写输入框（输入框保留用户原始输入，不显示规范化或夹值后的结果）。

  2. 立即构建设置面板（要求徽章已在页面上、且尚无设置面板，否则跳过）。
  3. 加载外部依赖（Font Awesome 样式表 + 滚动条样式）。
  4. 绑定设置按钮开关逻辑（要求按钮、面板、遮罩都已存在）。
  5. 异步等待章节容器就绪；就绪后尝试把同一徽章挂载到位置二，再次尝试构建设置面板与绑定开关（均为幂等）。
  6. 启动 DOM 重绑定观察器（第 10 节）。

### 9. 启动时清理无效记录

- **L-69** 启动时、在任何 UI 之前，对"当前存储后端"中所有以 `Youtube_SaveResume_Progress-` 为前缀的键逐条检查（只处理当前存储模式下的后端）。
- **L-70** 值无法解析为 JSON，或解析结果为空/非对象：删除该键。
- **L-71** 视频名字段规则：
  - 不是字符串：改为 `Unknown Title`，需要回写。
  - 是字符串但去空白后为空：改为 `Unknown Title`，需要回写。
  - 去空白后与原值不同：改为去空白后的值，需要回写。
- **L-72** 若（去空白、转小写后的）视频名与（去空白、转小写后的）原始标题字段都非空且相等：视频名改为 `Unknown Title`，需要回写（即"与原标题相同的自定义名"不被视为自定义名）。
- **L-73** 需要回写的记录以 JSON 字符串写回原键；其余字段保持不变。处理任一记录时发生异常则删除该键。

### 10. DOM 重绑定观察器

- **L-74** 在 `document.body` 上开启一个观察整个子树子节点增删的观察器，常驻、永不断开。
- **L-75** 每批变更中：
  - 若有被移除的节点自身带类名 `last-save-info-container`：新建徽章并尝试挂载到位置一，尝试构建设置面板，标记需要重绑。
  - 若有新增节点的 id 为 `movie_player`，或自身带类名 `ytp-chapter-container`：新建徽章，依次尝试挂载到位置一、位置二，尝试构建设置面板，标记需要重绑。
- **L-76** 若标记需要重绑：确保宿主根节点下存在遮罩（类名 `ysrp-backdrop`，不存在则创建：视口固定铺满、背景为主题遮罩色、z-index 9998、初始隐藏），然后重新绑定设置开关。
- **L-77** 上述"新建徽章"在页面已有徽章时为空操作，所有挂载/构建步骤均为幂等。

### 11. 启动流程（Bootstrap）

- **L-78** 脚本加载后立即：
  1. 确定并记录当前存储模式（首次会探测并持久化）。
  2. 执行无效记录清理（第 9 节）。
  3. 异步等待页面出现 `#movie_player`（已存在则立即）；出现后：先确保遮罩存在（避免首次点击时的竞态），再执行界面初始化（第 8 节），然后启动一个每 500 ms 的轮询——当"尚未恢复过进度、播放器存在、当前视频有已保存进度、视频时长 > 0"同时满足时，把播放位置跳转到已保存进度，标记已恢复，并停止轮询。
  4. 不等待播放器，立即启动每 1500 ms 一次的"保存当前播放进度"定时器（常驻）。

### 已知问题 / 怪异行为

- **L-Q1** 语言切换后的状态提示几乎不可见："语言偏好已更新。"写入状态行后约 50 ms 整个面板即被重建，新面板状态行默认隐藏，用户基本看不到该提示。
- **L-Q2** "当前已使用该语言。"提示在正常操作下不可达：点击已选中的行不会触发任何处理，隐藏单选框也无法直接点击。
- **L-Q3** 选择 `auto` 时即使实际语言不变（例如浏览器本就是中文且原偏好为 `zh`），也会触发完整的界面重建。
- **L-Q4** 语言选项中 `zh`/`en` 的名称、徽标、提示固定为 "中文 / 始终使用简体中文。" 与 "English / Always use English."，不随界面语言变化；只有 `auto` 项是双语的。翻译表中另有一套 "Chinese/English/ZH/EN/中文/英文" 等文案以及 "为脚本 UI 选择显示语言。" 描述，但实际界面未使用（只有标签名 "Display"/"界面" 走了翻译表）。
- **L-Q5** 语言显示名只区分 `zh` 与其他，任何非 `zh` 均显示 "English"。
- **L-Q6** 字幕设置中把字段清空不会清除已存设置：空的接口地址/模型/密钥被视为"未提供"而保留旧值，因此无法通过界面清空 API 密钥（默认密钥 `sk-asdlfjalalfja` 永远存在）。
- **L-Q7** 保存后不回写输入框：接口地址规范化、超时夹值（如输入 0.5 或 120）都不会反映在输入框中，用户看到的值与实际生效值可能不一致，直至面板重建。
- **L-Q8** 超时允许小数分钟（如 1.5 → 90000 ms），但再次显示时会四舍五入为整数分钟。
- **L-Q9** 接口地址若带有非标准路径（如 `https://host/api`），不会自动追加 `/v1/chat/completions`；只有路径为空或 `/` 时才补全。
- **L-Q10** 字幕页面监听 `ysrp-current-video-status` 的事件处理器挂在 `document` 上且从不移除；每次面板重建（如切换语言）都会新增一个，旧的已脱离 DOM 的面板仍持续被更新（轻微内存泄漏）。
- **L-Q11** "未检测到可用的影片"分支在实践中几乎不会出现，因为缓存的视频标题信息始终是一个对象；标题加载期间会显示中文占位文字 "正在获取标题…"（即使界面为英文），或显示 `Unknown Title`。
- **L-Q12** 章节容器挂载基本无效：初始化时徽章已挂到 `.ytp-left-controls`，随后在章节容器就绪时因"页面已有徽章"而跳过；只有当左侧控制栏不存在时才会落到章节容器。观察器中新增 `movie_player`/章节容器时的重建同理多为空操作。
- **L-Q13** 观察器在徽章被移除时只尝试挂载到位置一，不尝试章节容器。
- **L-Q14** 徽章重建（语言切换、被移除后重建）后文字回到 "Loading..."/"加载中..."，直到下一次保存周期（最多约 1.5 s，且仅在保存流程实际写入时）才更新。
- **L-Q15** Font Awesome 样式表在每次执行界面初始化时都会追加一次（正常只执行一次）；加载失败时所有图标位置为空白，无回退。
- **L-Q16** 进度恢复轮询在每次页面加载只运行到恢复成功为止；若当前视频无已保存进度，该 500 ms 轮询会一直运行不停止。
- **L-Q17** 保存定时器在播放器出现之前就已开始运行，依赖保存流程自身判断播放器是否存在。
- **L-Q18** 无效记录清理仅作用于当前存储模式的后端，另一后端中的坏数据不会被清理；它还会把"与原始标题相同的自定义名"重置为 `Unknown Title`，若该记录随后需要显示原标题则依赖其他流程重新获取。
- **L-Q19** 刷新判断"面板是否打开"使用"display 不为 `none`"；若面板 display 为空字符串（未初始化）会被误判为打开。
- **L-Q20** DOM 观察器监听整个 `document.body` 子树且常驻，在 YouTube 这类高频变更页面上每次变更都要遍历增删节点，存在性能开销。

## N-0 运行环境与构建

- **N-0.1** 用户脚本元数据：`@name` 为 `[Youtube] Video Memory [<日期>] v<版本>`，`@namespace` 保持 `0_V userscripts/Youtube Save & Resume Progress`（已安装用户可原地更新），`@match *://*.youtube.com/*`；授权 `GM_getValue` `GM_setValue` `GM_deleteValue` `GM_listValues` `GM_xmlhttpRequest`；`@connect oauth2.googleapis.com`、`@connect www.googleapis.com`；`@icon`、`@license MIT`、`@homepageURL https://github.com/0-V-linuxdo/Youtube-Memory`、`@supportURL …/issues`、`@update-log` 一行说明本版改动。
- **N-0.2** 源码使用 TypeScript，按 void++ 的目录约定组织：`src/api/`（插件管理、设置存储、记录存取、徽标、弹窗、标签注册等公共能力）、`src/utils/`（DOM 构建、多语言、存储、网络、常量）、`src/plugins/_core/<名称>/`（核心插件）、`src/plugins/<名称>/`（可选插件），入口 `src/index.ts`。

- **N-0.5** 存储格式（第一部分的记录键、字段、设置键、导出 JSON）全部保持兼容。新增字段和键见 N-1。

## N-1 数据格式新增

- **N-1.1** 记录新增可缺省字段：
  - `videoDuration`（秒）：保存进度时一并写入视频总时长，供记录列表计算任意视频的百分比。
  - `updatedAt`（ms）：记录内容（进度、标题、笔记、字幕）在本地被修改的时间；只改同步元数据时不更新。
  - `driveSync`：`{lastUploadAt, lastDownloadAt, remoteModifiedAt}`，云同步插件使用。
- **N-1.2** 所有写入都是“读取—合并—写回”，不认识的字段原样保留。
- **N-1.3** 新增设置键（与其它设置一样同时写 localStorage 与 GM，读取 localStorage 优先）：
  - `YSRP_Plugins`：JSON 字符串 `{"plugins": {"<插件名>": {"enabled": 布尔, …该插件的设置}}}`，缺省项取插件默认值。
  - `YSRP_DriveSettings`：JSON 字符串 `{clientId, clientSecret, refreshToken}`。含密钥，例外：读取时 GM 优先、其次 localStorage；写入只写 GM，GM 不可用时才写 localStorage。
  - `YSRP_DriveFullSyncDone`：`1` 表示首次全量上传已完成。
- **N-1.4** 导入时值若是对象（手工编辑过的备份）先序列化为字符串再写入，避免被启动清理删掉。

## N-2 进度引擎（替换第一部分中保存循环与恢复轮询的全部条目）

### N-2.1 原实现导致进度丢失的原因
| 编号 | 原因 | 场景 | 后果 |
|---|---|---|---|
| BUG-1 | “已恢复”标志全局只用一次，站内切换视频后不再恢复 | 在 YouTube 内点进一个看过的视频 | 新视频从 0 播放，保存循环把 0、1、2… 秒写进原存档，进度永久丢失（主因） |
| BUG-2 | 保存与恢复没有先后顺序 | 播放器尚未就绪、当前时间为 0 | 存档被写成 0，随后恢复读到 0 |
| BUG-3 | 地址栏视频 ID 与播放器实际视频不一致时照样保存 | 站内跳转的瞬间 | 旧视频的时间写进新视频记录 |
| BUG-4 | 广告期间照常保存和恢复 | 片头广告 | 恢复被广告吞掉，广告时间被写进存档 |
| BUG-5 | 暂停的标签页每 1.5 秒重复写入同一时间 | 两个标签页开同一视频 | 暂停的一页不断覆盖另一页的新进度 |
| BUG-6 | 存储写入异常被静默吞掉 | localStorage 配额满 | 不再保存且无提示 |
| BUG-7 | 界面里给 `innerHTML` 赋空字符串 | Trusted Types | 笔记按钮刷新抛异常 |
| BUG-8 | 列表百分比统一用当前视频时长计算 | 打开记录列表 | 其它视频百分比错误 |

### N-2.2 视频会话
- **N-2.2.1** 每个正在观看的视频 ID 对应一个会话，阶段依次为：等待 → （选择）→ 恢复 → 跟踪。视频 ID 取自地址栏 `v`。
- **N-2.2.2** 地址栏 ID 变化（站内跳转、前进后退、自动连播、播放列表下一首、刷新）即结束旧会话、建立新会话；离开观看页（`v` 为空）结束会话、不再保存。

### N-2.3 播放器就绪（同时满足）
1. `#movie_player` 存在且有 `getCurrentTime` `getDuration` `seekTo`；
2. `getVideoData().video_id` 等于会话 ID（取不到时不检查）；
3. `getDuration() > 0`；
4. 不在广告中：`#movie_player` 没有 `ad-showing` / `ad-interrupting` 类。

### N-2.4 恢复
- **N-2.4.1** 会话建立后、恢复结束前不保存任何东西。
- **N-2.4.2** 播放器就绪后：没有存档或存档 ≤ 1 秒 → 不恢复；存档距结尾 < 5 秒（已看完）→ 从头播放；地址栏带时间参数且与存档冲突 → 选择弹窗（N-3）；否则跳到存档位置。
- **N-2.4.3** 跳转后确认当前时间与存档相差 ≤ 3 秒，且连续确认 2 次才算成功；YouTube 把位置改回去（它自己的“继续观看”、广告结束、切换画质）时重新跳转，最多 8 次、总共约 15 秒。
- **N-2.4.4** 广告期间一直等待，广告结束后再恢复。直播（`getVideoData().isLive`）不恢复也不保存。
- **N-2.4.5** 恢复结束（成功、跳过或放弃）后进入跟踪；成功时徽标短暂显示“已恢复 m:ss / Resumed m:ss”。
- **N-2.4.6** 恢复前钩子：可选插件可登记“恢复前”异步任务（云同步用它拉取云端记录）。引擎在读取存档前等待这些任务，最多 4 秒，期间徽标显示“正在同步… / Syncing…”；超时或失败按本地数据继续。

### N-2.5 保存（只在跟踪阶段）
- **N-2.5.1** 每 1.5 秒检查一次；另外在 `<video>` 的 `pause`、`seeked`，页面转入后台（`visibilitychange`）、`pagehide`、站内跳转开始（`yt-navigate-start`）时立即写入。
- **N-2.5.2** 只在播放器就绪时读取当前时间；只有与上次写入的值相差 ≥ 0.5 秒才写。
- **N-2.5.3** 写入目标永远是会话 ID；切换瞬间用会话中最后一次就绪时读到的时间，而不是切换时播放器的读数。
- **N-2.5.4** 写入内容：已有记录合并 `videoProgress`、`saveDate`、`videoDuration`、`videoName`、`originalTitle`、`updatedAt`。
- **N-2.5.5** 写入失败：`console.error`，徽标显示“⚠ 保存失败 / Save failed”，悬停显示错误原因。
- **N-2.5.6** 写入成功后在 `document` 上派发 `ysrp-record-updated`（`detail: {videoId, videoProgress}`），打开中的记录列表只更新该行。

### N-2.6 列表百分比（替换第一部分记录行的百分比计算）
- 百分比 = `videoProgress / videoDuration`，保留 1 位小数；记录缺 `videoDuration` 时，若是当前视频用播放器时长，否则显示保存的位置 `M:SS`。

## N-3 时间戳链接与存档冲突时的选择弹窗（新需求）

- **N-3.1** 触发：地址栏带 `t=` / `start=` / `#t=`（支持 `90`、`90s`、`1m30s`、`1h2m3s`），存档满足恢复条件（> 1 秒且距结尾 ≥ 5 秒），且链接时间与存档相差 > 3 秒。相差 ≤ 3 秒或没有可恢复存档时不弹窗，按链接时间播放。
- **N-3.2** 弹窗是 HTML 界面，挂在 `#movie_player` 内居中（全屏时也能看到），宽 360px（不超过播放器宽度减 32px），圆角 16px，带阴影，配色同设置界面（N-5.3）。内容：标题“从哪里继续播放？ / Where to continue?”；说明“这个链接指定的时间与你上次的进度不同。 / This link starts at a different time than your saved progress.”；两个按钮并排：“上次进度 m:ss / Saved progress m:ss”（`.ysrp-resume-saved`，实心主按钮，默认聚焦）和“链接时间 m:ss / Link time m:ss”（`.ysrp-resume-link`，描边按钮）。
- **N-3.3** 弹出时暂停视频，徽标显示“请选择播放位置… / Choose a position…”；选择前不保存，存档保持原值。在弹窗上点击、按键不传给播放器。
- **N-3.4** 选“上次进度”→ 按 N-2.4 恢复到存档；选“链接时间”或按 Esc → 直接进入跟踪，从链接时间开始保存。弹出前在播放的，选择后继续播放。
- **N-3.5** 站内跳到其它视频时弹窗自动关闭，未作选择的视频存档不变。

## N-4 插件架构（参照 void++）

- **N-4.1** 每个功能是一个插件，定义包含：内部名称、显示名（中英）、说明（中英）、作者列表、图标（Font Awesome 名）、`enabledByDefault`、`required`（核心插件，不能关闭）、设置项定义、`start()` / `stop()`。插件还可以：贡献一个设置标签（分组、顺序、图标、标题、内容）、贡献记录行按钮及其展开面板、登记“恢复前”钩子。
- **N-4.2** 是否启用：核心插件始终启用；其它插件取 `YSRP_Plugins` 中的 `enabled`，没有则取 `enabledByDefault`。
- **N-4.3** 启动顺序：核心插件（进度引擎、播放器徽标、设置弹窗）先启动，然后其它插件。某个插件启动失败只记录日志，不影响其它插件和进度保存。
- **N-4.4** 运行中开关立即生效并保存，无需刷新：关闭时移除该插件添加的一切（DOM、监听器、定时器、样式、标签、行按钮），打开时重新添加。
- **N-4.5** 设置项类型：开关、文本、数字、下拉选择；每项有中英说明和默认值，可设为隐藏（不在界面里显示）。值保存在 `YSRP_Plugins` 该插件名下，修改即保存并通知插件。
- **N-4.6** 插件清单：

## N-7 云同步插件（新需求，替代 v1.4.0 的 Google Drive 自动同步）

- **N-7.1 凭据** 用户自己的 Google OAuth 客户端 ID、客户端密钥和 refresh token（需 Drive 权限），存 `YSRP_DriveSettings`。三项不全时不发任何请求，只在标签里提示填写。
- **N-7.2 访问令牌** `POST https://oauth2.googleapis.com/token`，表单 `client_id`、`client_secret`、`refresh_token`、`grant_type=refresh_token`；令牌缓存到过期前 60 秒。Drive 返回 401 时丢弃缓存，重新换取后重试一次。
- **N-7.3 文件夹** 在“我的云端硬盘”使用名为 `[Youtube] Video Memory` 的文件夹（`mimeType = application/vnd.google-apps.folder`、未删除），没有就创建；本页内缓存其 ID。
- **N-7.4 文件** 每个视频一个文件，名为 `<标题>｜<videoId>.json`：标题取记录的 `videoName`，去掉控制字符，把 `\ / : * ? " < > |` 换成 `-`，最长 120 字符，为空用 `Unknown Title`。内容 `{"version": "2", "videoId", "videoUrl": "https://www.youtube.com/watch?v=<id>", "exportedAt": <ms>, "record": <记录，去掉 driveSync>}`。从文件名末尾的 `｜<id>` 或 `[<id>]` 解析视频 ID。
- **N-7.5 查找** 在文件夹内查 `name contains '<id>'`、`mimeType = 'application/json'`、未删除，按修改时间倒序，只认解析出的 ID 相等的文件；最新的一个是该视频的文件。
- **N-7.6 上传** 记录本地修改后（`updatedAt` 晚于 `driveSync.lastUploadAt`）排队：第一次修改后 1.5 秒上传，期间的修改合并（后续修改不推迟这个时间，否则每 1.5 秒一次的进度保存会让上传永远等不到）；同一视频两次上传至少间隔 15 秒（不到就推迟到 15 秒）；同一时刻只有一个上传。已有文件则更新内容（标题变了同时改名），否则新建；同一视频多余的文件删除。成功后写 `driveSync.lastUploadAt` 与 `remoteModifiedAt`（不改 `updatedAt`，不再次触发上传）。
- **N-7.7 删除** 在记录标签删除一条记录时，删除该视频的云端文件。导入、切换存储后端等批量操作不触发自动上传或删除。
- **N-7.8 打开视频时下载** 每次开始一个视频会话时，通过恢复前钩子（N-2.4.6）拉取该视频的云端文件：云端修改时间晚于本地 `updatedAt`（缺省为 0）、晚于 `driveSync.lastDownloadAt`，且不是自己刚上传的（不等于 `remoteModifiedAt`）时，用云端记录覆盖本地同名字段（本地独有字段保留），把 `lastDownloadAt`、`lastUploadAt` 设为当前时间，这次写入不触发上传。云端没有文件但本地有记录时排队上传。
- **N-7.9 首次全量** 凭据齐全且 `YSRP_DriveFullSyncDone` 未设置时，上传全部本地记录，完成后写入该标记。若云端有 v1.4.0 早期的单文件 `[Youtube] Video Memory Sync.json`（格式同导出 JSON 的 `entries`），把其中本地没有或 `saveDate` 更新的记录导入本地（不删除该文件）。
- **N-7.10 状态** 标签内状态行显示：未配置 / 同步中（已完成 N / 共 M）/ 已同步（时间）/ 已推迟 / 出错（原因）；同时在 `document` 上派发 `ysrp-drive-sync-status`（`detail: {state, done, total, message}`，`state` 取 `start` `progress` `done` `deferred` `idle` `error`）。
- **N-7.11 标签**“云同步 / Drive sync”标签内两张卡片：
  - “Google Drive 同步”：客户端 ID、客户端密钥（可显示/隐藏）、refresh token（可显示/隐藏）三个输入框；“保存并验证 / Save & verify”（保存后立即换取一次令牌，显示成功或错误；首次成功后开始 N-7.9）；“全部上传 / Upload all”；状态行。
  - “如何获取凭据”：简短步骤说明（在 Google Cloud 建 OAuth 客户端、启用 Drive API、用 OAuth Playground 取得 refresh token）。
- **N-7.12** 同步出错不影响进度保存和恢复。网络请求优先 `GM_xmlhttpRequest`，不可用时用 `fetch`。
